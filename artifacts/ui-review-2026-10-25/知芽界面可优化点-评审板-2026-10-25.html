知芽 TreeLearn 界面校样，2026-10-25。依据是 Docs/04-ux-design/design-system/tokens.json 与两端生产代码，不是示意稿。

概念和纪律都在水准上，
卡住上限的是「读起来对不对」这一层。

安卓原生面和 Web／桌面面的视觉母题（生长绿、纸感、玻璃五面、一题一树）是立得住的，token 系统的纪律也少见地严。问题集中在字面、图标语义、行长、标签尺寸、纵向预算这五处——它们都不是「不够好看」，是用户在错误的机器上、错误的时刻，读到的不是设计稿想让他读到的东西。

六维取的是工作室判断，不是加权公式。「一题一树，慢慢长」不是贴在页面上的口号，它长在导航项、空态文案、统计口径和整块森林页的结构上——盖住文字，两棵树加等高线仍然认得出这是知芽。这是这个项目最贵的资产，任何后续改动都不该拿它换统一性。扣的两分在：首页本身没有承担这个母题，它是一张通用的对话首页。功能性 6 分扣在导航与阅读的物理层：底部标签栏只有两项、设置入口画成太阳、阅读正文 48 字一行、标签字号 11px。这几处都在「用户能不能顺利读到下一句」的层面，不在审美层面。

跨面四条

同时影响安卓与 Web／桌面，改一处不如改一套

严重

桌面端和 Web 没有随包字体，衬线身份由宿主系统兜底

证据离线包 frontend/dist-offline/index.html 里 @font-face 出现 0 次、字体 CDN 出现 0 次，frontend/ 下没有 fonts 目录；同一时间 APK 里放着 noto_serif_sc.otf，24,427,224 字节。

后果--serif 的栈是 'Noto Serif SC','Songti SC',Georgia,serif。没装 Noto Serif SC 的 Windows——正是 1.0.0 便携 exe 的目标机——会依次落到 Georgia（没有中文字形）再落到 generic serif，也就是宋体。品牌标题和阅读页大标题在用户机器上不是设计稿那个字面，而 Android 端是。同一份 tokens.json，两端两种字面。

为什么截图看不出这台评审机装了 Noto Serif SC 和 Noto Sans SC（注册表 366 条字体里查到），所以下面所有 Web 截图都是「对的」。这条只能靠代码判定。

改法把 APK 那份 otf 做子集（GB2312 常用 6763 字 + 拉丁数字标点，约 3–5MB），base64 内嵌进离线包，让 Web 和 exe 与 Android 用同一个字面；同时在 --serif 里补一个 Windows 上真实存在的中文衬线，把降级变成明确决定而不是随机结果。

重要

「设置」图标画的是一轮太阳

证据android/app/src/main/res/drawable/ic_chat_gear.xml 与 frontend/src/components/Icon.tsx 的 chat_gear 共用同一条 pathData：中心一个圆，外加八条放射短线。文件头注释写着 "Gear (prototype icons.tsx IGear)"——从原型起它就不是齿轮。

影响面它是 Web 侧栏「设置」的图标，也是安卓首页右上角唯一的设置入口。用户读到的是「亮度」或「主题切换」，点下去进的是 API Key 管理。

改法两端同批换成真齿轮或滑杆（sliders）。顺带一个流程问题：颜色 token 有 check_design_tokens.py 守门，图标没有——同一份 pathData 手抄在两端，抄错或改漏都不会报警。建议把图标纳入 parity 守面。

重要

标签层是 11px / 11sp，而且用在导航文字上

证据tokens.json 的 fs-cap = 11px，Web 侧 12 处以上消费者；android/.../values/dimens.xml 的 text_cap = 11sp，底部标签栏「主页 / 学习库」正是用它（标签栏本身高 50dp，触控尺寸是够的，问题只在字）。

为什么算问题12px 是中文界面小字可读性的下限，11px 的中文在 1080p 手机和 Windows 桌面上会先掉横画。导航标签是全应用点击率最高的一行字，不该是字号最小的一行。

改法二选一：把 fs-cap 提到 12px，或把导航标签降到 fs-sm（13px）。这是 token 级改动，四处同批：原型 :root → tokens.json → 重新生成 tokens.css → 安卓 dimens.xml，然后跑 check_design_tokens.py。

优化

app.css 425 行是死样式表，还在打进 508K 离线包

证据main.tsx:11 仍 import "./styles/app.css"。抽样它里面 12 个类名去 tsx 里找消费者，10 个是 0 命中：appbar-brand、chat-answer-run、chat-row、home-topic、notice-text、glass-surface、tab-bar、screen-root、model-chip、word-menu。

真正的代价已声明放弃的 --kai 在这张死表里还有两个「消费者」（appbar-brand、chat-answer-run）。tokens.json 的 note 写着「楷体身份已放弃，本片保留不删，退役待后续清理」——但只要这两个选择器还在 CSS 里，任何按 CSS grep 判字体存活率的守门都会误报 kai 还在用，退役就永远做不掉。

改法删表，然后按 note 自己写的计划把 --kai 从 tokens.json 退掉。注意 .chat-answer-run 是从安卓 view_chat_answer_text.xml 的 id 抄来的，删之前确认安卓侧同名资源不受影响。

逐屏批注

每屏三条以内，按严重度排。截图是真机与真渲染，不是示意稿。

  1. 重要　侧栏一列里混了三种性质的东西

    主页 / 学习库 / 设置 是路由，我的森林 是路由卡，最近学习 是内容——三者共用 240px 一列、同一套 hover 底色。实测 .app-sidebar 宽 240、.page 宽 960，侧栏只有 240 的预算，却要同时承担导航和历史列表。

    改法：最近学习降一档（13px + --ink3、去掉 hover 底色），或整块移出侧栏进内容列底部；侧栏只留路由。

  2. 重要　主输入卡的下沿是一句自我否定

    「发送与上传尚未接通；点推荐问题或历史主题进入对话。」13px 灰字，位置在 CTA 卡内部下沿。用户走到首页、看到输入框、输入框说自己不能用。

    不接通是项目有意的范围决定，诚实文案是规则要求的，这两点都不该改；该改的只有位置——挪到卡外下方 8px。后半句是当前唯一真实路径，应该做成可点，而不是用分号跟在前半句后面。

  3. 优化　历史主题行的视线落点和操作落点分家

    标题从 x=366 起，chevron 贴到 960px 列的最右端，中间塞 2–3 行摘要。整行确实可点，但眼睛找的是标题，手找的是箭头，中间隔着两行正文密度的字。

    改法：摘要收成 1 行、2 行截断；「1 个分支 · 3天前」紧跟标题右侧 8px，不要另起一行。

  1. 重要　阅读正文实测 48 个中文字一行

    Playwright 渲染离线包量到 .chat-answer 宽 720px、font-size: 15px → 每行约 48 个汉字。中文长文的舒适区间是 32–40 字，超过之后换行找回行首的成本陡增，这是阅读类产品最实在的一处漏。

    改法：给 .chat-answer 加 max-width: 620px（约 41 字）。项目里已有先例——pages.css:721 给 .persona-card 用了 max-width: 62ch，反而阅读正文没有约束。选区浮条和引用条跟着这个列宽走。

  2. 优化　字号档位中段是空的，层级只能靠颜色撑

    token 序列是 11 / 13 / 15 / 16 / 20 / 26 / 30：16 到 20 之间没有第三级标题，11 到 13 之间没有小字。结果是「3天前」「1 个分支」这类 meta 和导航标签挤在同一档。

    改法：先不加 token。把「3天前」从 fs-cap 提到 fs-sm，中段的空缺等真出现第三级需求时再决定。

  3. 优化　同一句「未接通」在第二屏又出现一次

    输入卡底部「发送、上传与分支创建尚未接通；这里可以写草稿，也可以复制回答。」和首页那条是同一个模式：说明写在动作的容器里。

    改法：全站把「未接通」收敛成一种表达——禁用态本身承担「不能点」，一次说明承担「为什么」。不要每进一屏读到一行新的灰字道歉。

  1. 重要　隐喻到位了，信息没进来

    约 1200×800 的场地上两棵树。树没有名字、没有 hover 标题、没有时间；全场唯一的量化信息是底部一行 11px 的「2 棵树 · 3 段枝」。这是产品的招牌屏，也是信息密度最低的一屏。

    改法：树冠下方 12px / --ink2 标主题名（8 字截断，hover 给全名）；底部计数提到 fs-sm。加字不等于破坏留白——现在是留白吃掉了内容。

  2. 优化　右上角圆圈里的「N」没有任何解释

    场地隐喻里唯一的操作符号，没有 hover 态、没有 aria-label，看不出是指北、刷新还是缩放复位。

    改法：要么去掉（场地不需要方位），要么补 hover 说明和可访问名。

  3. 优化　等高线是全场唯一的纹理，但它几乎看不见

    压在 rgba(22,36,28,.06) 一档。项目对「看不见」是有量法的：2026-10-22 因为真机四角跨度只有 7.7 L，把 mist-base 整体加深过。

    改法：用同一把尺子量等高线的 ΔL。要么承认看不见就别画，要么按实测抬到能穿过 check_glass_depth.py 那条 8 L 线。

  1. 重要　首屏纵向预算：可操作的东西落在中线以下

    状态栏 + 玻璃 app bar 之后，品牌 hero「知芽」加 tagline 吃掉上半屏，输入卡落在屏幕中线附近。手机上第一屏唯一能点的是输入卡和被裁掉的半张推荐卡。

    这条是目测自截图，没做 bounds 实测：今天试图用 uiautomator dump 抓 com.treelearn 首页失败（启动报 Error type 3，前台是另一个应用）。改法方向明确——hero 与 tagline 并成一行，或把 hero 上边距压到 s8——但数值要等一次真机 bounds 才能定。

  2. 重要　推荐区右列被裁成半张卡，文字断成半句

    「从注意力可视化至 / 法的能力边界」——读起来像渲染坏了，实际是 marquee 的露出量。半句话比没有话更糟：用户会以为是页面出错，而不是「还有更多」。

    改法：露出量至少给到卡宽的 60%，或换 PagerSnap 整卡翻页。同一类问题在学习库第三张卡的摘要末尾也出现了（「符…」）。

  3. 优化　四张推荐卡挂着同一个「顺着你学的」

    同屏重复四次的标签不携带任何区分信息，只吃掉每张卡一行高度（Web 两张卡也一样）。

    改法：pill 只在「猜你想学」区块标题处出现一次，卡内保留 sparkle 图标足够。

  1. 严重　中断卡把风险提示排成了按钮的副标题

    「重试不新增消息或分支」和「重试」按钮挤在同一行、按钮右对齐。这句是用户决定点不点之前必须读到的风险说明，现在它读起来像按钮的注释文字，字号还比主句小一档。

    改法：主句一行、说明独占第二行、按钮第三行左对齐；或按钮移到卡片右上角，把下方整行留给说明。错误态是产品可信度最脆弱的一屏，值得单独走一遍排版。

  2. 重要　顶栏标题截断到约 10 字，还要挤三个图标

    「注意力权重与因果贡献不等…」——标题被截，同时一行里还排着分享、地图、设置三个动作。用户判断「我在哪棵树的哪个分支」全靠这行字。

    改法：标题独占一行，第三个动作收进溢出菜单；或标题降到副标题位（13px），主标题位留给分支名。

  3. 优化　空态只有文字，没有出口

    对话页大面积留白；总览画布空态是「这棵树还没有分支。」一行字。两句文案都很克制，但都没给下一步。

    改法：空态补一个主按钮（回首页提问 / 去森林看看），别让留白变成死路。

  1. 重要　「已完成 0」也占一整段 44dp 分段位

    分段控件占满一行，两档里有一档恒为 0。空分段是纯死重量，还把它下面第一条真实内容往下推了 44dp。

    改法：为 0 的那一档收成计数徽标（不占分段位），只有一档有内容时直接隐藏分段控件。

  2. 优化　搜索框 placeholder 写的是字段清单

    「标题、问题、回答、锚定原文…」——这是给实现者看的可搜范围，不是给用户的提示。用户不需要被提醒字段名，需要知道现在能不能搜、搜什么。

    改法：缩短成「搜索主题、回答或原文」，把可搜范围交给 filter 或结果页的说明。

  3. 优化　卡片摘要固定两行，第三张末尾出现「符…」

    按字符数硬截断，截在词中间。和首页 marquee 是同一类问题。

    改法：按句末标点截断补省略号；或给摘要一个真实的最小信息量（不足一句就整行不显示）。

这张板子自己用的字体是故意的。它通体无衬线，没有用它在评审的那款 Noto Serif SC——因为 X1 说的就是那款衬线在没装字体的机器上会掉成宋体。一张校样不该带着被校的那个缺陷。

如果要把这些改法画成改后对照。那是新的视觉设计，按规矩先出三个方向给你选，选定之后才动手。三方向的价值在这里很具体：X1（字面）和 X3（标签尺寸）是 token 级、几乎无争议的必修；D1（首页纵向预算）和 C1（森林信息密度）是有取舍的方向题——一个把品牌让给效率，一个把留白让给信息，选多狠是产品决定，不是排版决定。别把它们和必修项捆在同一次改动里。
