## Problem（问题与背景）

- 问题/背景：现在没有任何「一个事务里把首个主题写完整」的入口。五类行（topics 1 / branches 1 根 / messages 2 / generation_operations 1）如果分多次写入，中途被打断就会留下半成品。观察到的现象出现在恢复路径上：重启后恢复逻辑看到「有 topic 没有根分支」或「有分支没有 operation」，推导出一棵空树，用户看到首屏空白且重试不了。推测的原因是写入没有事务边界，而不是恢复算法本身有缺陷。
- 用户/场景：用户发出根问题后立刻断网或杀进程，随后重启应用。

## Users and scenarios（用户与场景）

- 一人开发自用；本期只有提出者本人使用，没有第二位使用者，也没有服务端账号体系。

## Expected outcome（预期结果）

- 预期结果：`:data` 提供一个事务入口，单个事务内写入五类行并返回显式提交结果；重启后要么看到完整的主题树加上一个可重试的生成操作，要么一行都没有，绝不出现空树。

## Core flow（核心流程）

- 核心流程（含中断、撤销、重试）：topic → 根 branch → 用户 message → AI message → operation；中断时整体回滚，用户重新发一次即可，不存在「修半成品」这种操作；撤销就是删掉该主题（级联），不新增撤销入口。
- 输入/输出：输入是已由 `:core` 工厂构造好的 `Topic`/`Branch`/`Message` 与 operation 构造参数；输出是显式成功结果（含新主题 id）或分类错误。
- 状态与异常：失败必须回滚到该主题零行；错误必须是分类错误，不允许裸 `SQLException`/`IllegalStateException` 穿透调用方；重复创建同一主题 id 要有明确错误。
