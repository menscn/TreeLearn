DECISION 1 - branch title on a hit row (product goal: "hit shows the branch it belongs to")
The prototype row is: type chip + branch title (prominent) + snippet + ancestor path (renderSearch at prototype :2215-2231).
Ancestor path needs a tree walk; NOT in this task's scope and not in its In scope list => omitted and recorded as a gap.
Branch title: resolved by the HOST, not the screen. MainActivity implements SearchPresenter.Sink; in render(state) it resolves the distinct branch ids of state.hits through the existing ChatStore.branch port on container.background(), then posts searchScreen.show(state, titles) to the ui thread. The screen never reads a store and never filters a hit (no second decision point: it draws exactly state.hits in order).
Cost: one small Map + a re-render; benefit: the row names the branch, which is the whole point of "I forgot which branch".
