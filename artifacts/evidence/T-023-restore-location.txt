## 结论（计数与落点由本脚本从上面各命令的捕获输出机械提取，非手写）

- Command 1：生产源码里 `AnswerRevision.restore` 命中 3 行，落在 AnswerRevisionDao.java、TreeLearnSchema.java 内。
  其中真实调用 1 处（`AnswerRevisionDao.java:112`）。注意这条模式的边界：只有写作 `AnswerRevision.restore(` 的行才算调用，
  而 `:core` 里的方法定义写作 `AnswerRevision restore(`（没有点号），因此本行既不计入调用，也不出现在本轮捕获里。
- Command 2：井号写法（javadoc 交叉引用）命中 2 行，位于 AnswerRevisionDao.java —— 它们是文字引用，不是调用，
  因此断言 (a) 必须按「调用点」而不是「提及次数」来读。
- Command 3：放宽到整个 `android/` 后共 9 行命中；`:app` 的 androidTest 侧直接调用为 0 处 ——
  本任务的用例不自己构造 revision，一律走 `AnswerRevision.create`，所以测试侧不会成为再水合的第二个入口。
- Command 4：写路径工厂 `AnswerRevision.create` 在生产源码里命中 4 行，落在 GenerationOperation.java、GenerationStabilizer.java；
  调用点 `GenerationStabilizer.java:126` 即 `GenerationStabilizer` 的落盘入口，断言 (b) 的「写路径走 create」由此成立。
- Command 5：全仓 `.java` 中 `GenerationOperation.restore`/`GenerationOperation#restore` 零命中，断言 (c) 成立。
  EXITCODE=1 是 grep 的「无匹配」语义，不是执行失败。
- Command 6：`GenerationOperation.start` 命中 6 处 —— 该类型只有这一个创建入口，与断言 (c) 互证：
  没有 `restore`，行形态才是读取 attempt 的唯一方式。
- Command 7：`markStable` 命中 3 行，位于 GenerationOperationDao.java、GenerationStabilizer.java；其中定义是 `GenerationOperationDao.java:168`（包私有），
  `public` 修饰的命中 0 处 —— 即「唯一能把行写成 STABLE 的入口是 stabilize 事务内部的那次调用」，
  外部没有第二条路可以绕过 revision 创建把 attempt 置为 STABLE。
- Command 8：dao 包内 `CREATE`/`ALTER`/`DROP` 零命中，即本任务新增的生产类没有引入任何 DDL。

### 本文件没有覆盖到的（如实列出）

- 断言 (a) 的「只允许出现在只读映射内」是**结构判断**：Command 1 证明调用点唯一（`AnswerRevisionDao` 内），
  该调用位于 `read(Cursor)` 这个私有只读映射中，由源码阅读确认，检索命令本身不区分方法名。
- 断言 (b) 的「重试、重置、分叉、迁移、回填」这些写路径本任务尚未实现（属 T-006/T-008/T-009/T-010），
