visual evidence - library back arrow (2026-09-28)
================================================

WHY
---
User report (screenshot Clipboard_Screenshot.png): "学习库没有返回按钮" - the library page
header carried no back control while the settings page header did, so the two headers of the
same kind of page (both first-level tabs) read as different styles.

RULING
------
User picked option (a): draw a real back arrow on the library header, same form as the settings
header. Behaviour of the arrow = the same request the system back gesture makes, and it is
consumed in the same order: a live query is left first (the library's own lists come back), and a
library already showing its lists steps out to the home tab.

CHANGES
-------
- res/layout/screen_library_body.xml  empty touch_min lead View -> ImageView id=library_back
                                     (ic_nav_back, tl_green_deep tint, borderless bg, -8dp start)
- res/values/strings.xml              + cd_library_back
- screen/LibraryScreen.java           + setOnBackPressed(Runnable); arrow wired in ctor;
                                     leaveSearch() returns whether there was a query;
                                     showSearch() no longer paints the GUIDE pane (see below)
- library/LibraryPresenter.java       + onSearchLeft() - restores the library's own lists
- MainActivity.java                   showLibrary() binds the arrow; onBackRequested() library
                                     branch: clear the box first, then restore the lists, else home
- test/IconAssetsTest.java            + assertIconAction(..., "library_back", ...)
- androidTest/BottomTabShellInstrumentedTest.java  + theLibraryArrowLeavesTheSearchStateThenStepsBackToHome

SIDE EFFECT FOUND AND FIXED (not cosmetic)
------------------------------------------
The prototype's search is a separate second-level screen (renderSearch) whose empty state is the
guide "输入关键词开始搜索". This implementation inlines search into the library, so an empty query
had no screen for that guide to belong to. Clearing the box therefore used to leave the search
scope line painted over the library's own lists. showSearch() now returns early for Pane.GUIDE, so
an empty box leaves the library's lists in place. This is what makes "leaving the search lands on
the library's lists" true rather than "lands on a guide with nowhere to stand".

CONCLUSION
----------
The library header draws the same back arrow as the settings header (step 1 vs step 5), and the
arrow behaves as one back request with two levels, matching the gesture: it leaves a live search
and restores the library's lists (steps 3->4), and with no query it steps out to the home tab
(step 2). Every gate is green. Device screenshots are the raw screencap output, archived under
artifacts/evidence/visual-2026-09-28-library-back/.
