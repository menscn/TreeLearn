# 事故二：别线提交操作吃掉本线未跟踪新增文件 EdgeFadeLayout.java

## 判定
- 15:03:17 本线写入 EdgeFadeLayout.java（新增未跟踪文件），md5 f791aae20df78647c8a869d305633325。
- 15:11:13 编译报 `RecommendationMarquee.java:60/104 找不到符号 EdgeFadeLayout`
  （同包无需 import，故只能是源文件缺失）。
- 15:12 核实：`ls android/.../screen/EdgeFadeLayout.java` → No such file or directory。
- 同期本线其余 5 个生产改动文件 + 2 个测试文件**全部存活且 md5 与写入时一致**
  （RecommendationMarquee d4a1f972… / Recommendation f389b01a… / HomePresenter 12ffb5f5…
   / dimens.xml d966e000… / screen_home_body.xml 730fd308…），即**只丢了唯一那个未跟踪新文件**。
- git reflog 同期出现新提交 `7f7ba2b fix(home): 首页 slogan 去掉句号`（作者：别线）。

## 根因
别线的提交/暂存流程在 15:03–15:11 窗口内触及工作区，未跟踪的新增文件是唯一会被
此类操作（`git checkout` / `git stash` / 部分 `git add` 后回退等）带走的对象；
已跟踪文件的修改则保留。**这是共写工作区的第二类干扰**（第一类是 fileHashes.lock）。

## 处置
1. 15:13 凭本轮对话中读到的完整源码逐字重建 EdgeFadeLayout.java；
2. 校验 md5 回到 f791aae20df78647c8a869d305633325、行数 114 —— 逐字节还原，非近似恢复；
3. 立即 `git add` 该文件与 HomeRecommendationStripTest.java，使其由 `??` 转为 `A`，
   此后别线的提交/清理不会再带走它们。
   注意：`git add` 时 Git 提示 `LF will be replaced by CRLF`，即工作区 LF 与
   索引 CRLF 的转换会发生，md5 可能在 Git 触碰后变化（本仓库既有约定）。

## 命令与退出码
$ cd android && ./gradlew --no-daemon --console=plain -PbuildDir=build-homefix \
    :app:compileDebugJavaWithJavac
EXITCODE=1   ← 15:11:13，失败原因 = EdgeFadeLayout.java 缺失（非语法错误）

$ md5sum android/app/src/main/java/com/treelearn/app/screen/EdgeFadeLayout.java
f791aae20df78647c8a869d305633325   ← 15:13 重建后，与 15:03 写入值一致
