### 1b. 第二轮变更（子分支列表 → 图标 + 数量徽标）

用户原话：「分支列表 对应的也是图标，**不要是文字**！」
原型依据：`知芽-TreeLearn-高保真原型-v1.1.html:1178` 画的是 `<ITree size={17}/><span className="ai-act-n">{N}</span>`，
即 **ITree 字形 + 右上角绿色数量徽标**（`.ai-act-n`，同文件 232 行）。Android 侧此前退化成了纯文本「子分支 N」。

| 文件 | 改动 |
|---|---|
| `android/app/src/main/res/layout/view_answer_actions.xml` | `act_children`：`Button`（文字）→ `FrameLayout`（44dp 热区）+ `ImageView`（`ic_nav_tree`，24dp，居中）+ `TextView`（`act_children_count`，右上角徽标） |
| `android/app/src/main/res/drawable/bg_count_badge.xml` | **新增**：绿色胶囊（`tl_green` 实底 + `space_s2` 圆角） |
| `android/app/src/main/java/com/treelearn/app/screen/AnswerActionBar.java` | `children` 字段 `Button`→`FrameLayout`，新增 `childrenCount`；`render` 内 `setText("子分支 N")` → `childrenCount.setText(String.valueOf(childBranchCount))` |
| `android/app/src/main/res/values/strings.xml` | 删 `chat_act_children_count`（徽标只放数字） |
| `IconAssetsTest.java` | `javaDrivenTextualActionsStayTextual` **反转**（旧断言「act_children 必须保持文字」已不成立）；新增 `theChildEntryDrawsAGlyphAndItsBadgeUsesTheBrandGreen` |
| `ChatMessageRowLayoutTest.java` | 新增 `theChildEntryIsAGlyphWithACountBadgeNotALabel`；新增 `elementWithBody()` 辅助（原 `elementAround()` 只取开标签，看不到 FrameLayout 的子节点） |

**未新增 token**：徽标用既有 `tl_green` + `space_s2`。

**第二轮踩到的坑（两条，各失败一次）**：
1. `bg_count_badge.xml` 首次 `Write` **未落盘**（并发写树期间静默丢失）→ `processDebugResources` 报
   `resource drawable/bg_count_badge not found`。**诊断法**：不要只信 Write 的 success 回执，立刻 `ls` 验在。
2. 补写时注释里写了 `background --green` → AAPT2 `ParseError: 注释中不允许出现字符串 "--"`，
   `mergeDebugResources FAILED`。**这是本仓已记录过的坑**（`ic_key.xml`/`bg_unread_dot.xml` 各踩过一次），
   注释里提 token 要写 `green`，不能照抄 CSS 变量写法。改后全树扫描确认 3 个改动 XML 的注释均无 `--`。

## 5. 两次先导失败的性质裁决（非 Kotlin 命中）

本 guard 在拿到 PASS 之前失败过两次，**均为 Gradle 构建缓存层的文件锁冲突，与 Kotlin 无关**：

| # | 失败任务 | 报错摘要 | 裁决 |
|---|---|---|---|
| 1 | `:app:compileDebugJavaWithJavac` | `Failed to load cache entry …: Unable to delete directory '…\intermediates\javac\debug\compileDebugJavaWithJavac\classes'` | 缓存淘汰时目录被占用（本仓多工作线并发写同一 `android/` 树，另有 Gradle 进程持有） |
| 2 | `:app:dexBuilderRelease` | `Failed to store cache entry …: Could not get file mode for '…\BlockingDerivedCaller$1.dex'` | 同上，缓存写入时文件被并发持有 |

判定为非 Kotlin 命中的依据：
1. 两次失败形态**不同**（一次读缓存淘汰、一次写缓存条目），且**都发生在 `verifyNoKotlinDex` 之前的构建阶段**，`verifyNoKotlinDex` 任务本身根本没有执行到。
2. 报错文本**不含任何 Kotlin 坐标或字节码**；唯一提到的产物 `BlockingDerivedCaller$1.dex`，其源文件是
   `android/app/src/main/java/com/treelearn/app/artifact/BlockingDerivedCaller.java` —— **Java 匿名内部类**（`$1`）。
3. `find android -name '*.kt' -o -name '*.kts'`（排除 `build/`）**为空**，源码树无 Kotlin。
4. 加 `--no-build-cache` 绕过缓存层后**一次通过**，→ 失败点确实在缓存，不在编译/校验逻辑。

> 与既有约定一致：`-q` 会吞掉 Gradle 的 "What went wrong"，故本文件引用的报错均来自**去 `-q` 的原始运行**。
> 唯一给出的 PASS 报告来自**加 `--no-build-cache` 的那次运行**，其命令行与运行模式已随本节如实记录。
