# 代码与文档一致性

读取时机：生产事实或当前态文档分析、修改与验收前。仅加载本任务命中的规则；正文约束沿用原适用范围，不因读取而进入 Harness。

## 代码与文档一致性 guard（Code-document alignment guard）

本 guard 适用于直接执行与 Harness 工作，是双向的：生产变更必须更新当前态文档，当前态文档变更必须用生产来源证明，而非从另一份文档复制。

### 权威边界

- 对**当前运行时行为**的主张，优先使用活动的生产代码与配置，其次是生成的 schemas/契约与 Flyway 迁移、然后是测试、最后才是当前文档。PRD、计划、已完成任务、原型、spike、发布说明与带日期的报告描述的是意图或历史，除非它们明确声明自己为当前态。
- 对**规范性约束**（如安全、授权、隐私、数据库治理、无状态、凭据归属、稳定的错误封装），即便当前代码违反，也不得削弱该规则。保留规范本身，用代码证据与 severity 记录实现偏差，并把代码修复单独路由。
- 可执行的示例、路由索引、响应示例、worker/队列矩阵、插件清单、表清单、启动命令与排障说明都是契约性文档；「只是注释/示例」不足以豁免——当它能指导实现或运维时同样受此约束。

### 必需的影响映射

每个变更的运行时事实都必须核对相应面；只更新受影响的文件，但即使无需编辑也要记录核对。

| 变更面 | 必须核对的相关文档 |
|---|---|
| 公共/内部 API 路由、DTO、状态、错误封装、header、SSE 事件、兼容别名 | 对应接口文档；生产者及仓库内每个消费者；后端服务路由变更还需更新对应服务 API 路由文档 |
| 用户流程、权限、状态迁移、UI 入口/返回路径、遥测语义 | 对应业务文档；相关工作区/模式行为如适用 |
| 服务边界、鉴权/凭据归属、队列/worker/并发、存储、权威表/数据流 | 对应架构文档与适用的治理文档 |
| 构建/启动命令、端口、代理、环境变量、依赖安装、健康/就绪行为 | 根与模块 README、文档入口，以及启动规则要求的 Docker/Compose/`.env.example` 检查 |
| Android SDK/来源、Manifest intent、Activity 生命周期、原生插件、系统 UI、仅限 Java/i18n 行为 | `android/README.md` 与相关的业务流程文档 |
| Flyway、SQLiteOpenHelper/schema/表变更 | 对应引擎的迁移权威来源加表清单、数据治理、架构及受影响的 API/业务文档 |

### 文档影响记录

生产/配置/契约任务或直接变更要报告完成前，其任务、PR 说明或最终执行记录必须说明：

- 变更的运行时事实及精确的权威代码/配置/迁移证据；
- 受影响的文档面与已更新的文件；
- 已核对的生产者、消费者、同级入口、兼容性与历史引用；
- 用于反向查找的旧术语或示例，以及是否仍有匹配项；
- 当无文档变更时，`documentation impact: none` 加上明确理由，以及证明该变更是行为中性的搜索/证据。

空泛的「无需文档」断言无效。文档默认在同一任务/变更中更新。延后关键文档更新需要获得明确的用户批准，并让工作保持 PARTIAL 或 blocked；仅建一个后续 issue 并不让当前变更完整。

对纯文档的当前态变更，反转证据方向：引用活动的生产者/消费者/配置/迁移事实，核对同级路径与兼容别名，不得把另一份文档当作唯一权威。接口文档与 API 路由索引变更需只读 `contract-guardian` 复核。带日期的报告与已被取代的运行手册应添加可见的历史快照说明并链接当前权威，而非静默改写历史。PRD 漂移要报告，不要自动编辑。

最低限度的文档验证是 `git diff --check`、UTF-8/替换字符扫描、对变更的 Markdown/HTML 做相对链接检查，以及针对被取代短语/示例的反向查找。项目 Harness 校验器在以下情况必须返回 FAIL：缺失影响记录、未复核的关键映射、与活动的生产者/消费者事实相矛盾的当前态主张，或把未标注的历史文档当作当前态。仅通过链接或拼写检查器无法豁免这些语义检查。
