# 共享状态与 Worker 标识

读取时机：状态存储、缓存、租约、锁、异步流程、轮询或后台任务设计与修改前。仅加载本任务命中的规则；正文约束沿用原适用范围，不因读取而进入 Harness。

## 适用性判定（先读这一段）

- 本规则的「跨实例无状态」「共享介质」「Java Worker Owner 标识」「Redis Cluster 多 key 原子性」条款针对**可横向扩容的服务端**。Treelearn V1 是 **Android 单机本地优先应用**（技术方案 §2.2）：无远程服务端实例、无 Redis、无跨实例请求路由、无租约/租借 worker，因此这些条款**不适用**。不得据此判 Android 本地任务 FAIL。
- 〔2026-10-15〕规划中的 `backend/` 是**仅监听本机环回地址的单进程桌面服务**（`Docs/spec/SPEC-2026-10-15-web-h5-android-parity.md`），它不引入横向扩容、共享介质或多实例路由，因此上一条仍判「不适用」。若它将来出现多实例、共享缓存或跨进程 worker，须回到本规则重新裁定；裁定变化时按 `.trae/rules/documentation.md` 回写本节，而不是只改任务记录。
- 仍然适用的内核：任何需要跨请求、跨组件或跨进程重启恢复的业务状态，不得只保存在 Activity/Fragment 字段、静态单例或进程内存；必须落到设备本地 SQLite 并由 Repository 作为唯一权威来源。应用级 `GenerationCoordinator` 允许持有进程内缓存，但代码注释或文档必须标注「非权威状态，恢复只读取 SQLite」（技术方案 §15）。
- 「提交实例 A、消费实例 B」的等价证据在本项目是：**提交后杀掉进程再冷启动，状态仍可从 SQLite 恢复**（技术方案 §7 的 `INTERRUPTED` 落定与手动重试）。
- 若将来引入**远程**后端、账号或云同步，或本机服务出现多实例、共享介质、跨进程 worker，本规则全文重新启用，并在引入任务中补齐跨实例证据。仅监听本机环回地址的单进程 `backend/`（阶段 7 规划）**不触发本句**——它与本节第二条「适用性判定」是同一个判定，不得两处各给一个结论。

## 无状态与跨实例验证

- 所有可横向扩容的服务必须保持无状态：不得把用户业务状态、任务进度、异步任务结果、轮询状态、锁、幂等标记或权限归属只保存在单个进程/JVM/后端服务实例内存、本地临时文件或容器私有磁盘中。需要跨请求、跨实例、重启后可恢复的状态必须落到 MySQL、Redis、MinIO 或其它明确共享的持久化/缓存介质。
- 新增轮询、后台任务、SSE、WebSocket、异步生成、文件处理、补偿任务或定时任务时，必须在实现和测试中证明「提交实例 A、查询/消费实例 B」可用；任务 ID 与用户/租户归属必须存放在共享介质并在查询时校验，不能依赖 sticky session。
- 允许进程内缓存的内容仅限配置、客户端连接、纯函数/可重建派生结果或性能优化缓存；缓存失效、实例重启或命中不同实例不得改变业务正确性。若使用进程内缓存，代码注释或文档需说明其不是权威状态。

## Java Worker Owner 标识规则

- 持久化到数据库或其它共享介质的 lease、lock、worker owner 标识必须使用固定应用前缀和有界随机标识；`backend` 统一复用项目内的 `WorkerOwnerId` 工具生成 `backend:<UUID>`。
- 禁止把 Pod 名、hostname、容器名或 JVM runtime name 拼入这类标识；不得通过扩大数据库字段来容纳部署环境名称。环境差异只能作为可观测诊断信息，不得参与租约或锁的正确性判断。

## Redis Cluster 多 key 原子性

- 新增或修改 `EVAL` / `EVALSHA`、事务或其它需要同槽的多 key 操作时，必须枚举生产路径最终组装的全部 key，并用客户端 slot 算法证明只落在一个 hash slot。Fake Redis 或 standalone Redis 的逻辑测试不能代替该证据。
- 必须同槽的业务 key 使用专属局部 hash tag，不得通过全局 tag 把无关 key 集中到一个 slot。如果 key 无法同槽，拆分操作时必须明确非原子中间态、幂等和补偿语义。
- hash tag 变更等同于 key 命名空间变更；完成前必须记录旧 key TTL、滚动发布的新旧状态分裂以及迁移/清理策略。详细案例按需补充到本任务、PR 或项目治理文档。
