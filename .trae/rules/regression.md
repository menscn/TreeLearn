# 防回归与行为证据

读取时机：行为修改、共享逻辑、回归修复或相应验收前。仅加载本任务命中的规则；正文约束沿用原适用范围，不因读取而进入 Harness。

## 防回归与行为证据 guard（Regression prevention and behavior evidence）

本 guard 适用于直接执行与 Harness 工作。它不把改动纳入 Harness、不要求新建记录文件，也不增加常规用户审批。证据保留在既有执行笔记或 PR 中；Harness 任务沿用其既有的 Scope、验收标准与验证报告小节。已完成的历史任务不重写；恢复的任务补足适用证据。

1. **编辑前评估真实影响。** 对共享函数、错误映射、资源配置或交互组件，检查生产者、消费者、同级入口与平台分支，记录具体路径与变更语义。小改动、单文件或仅前端的 diff 不能作为影响低微的证据。
2. **保留既有行为。** 行为变更前记录预期变更、需保留的旧行为、受影响入口及各自的验证方式。删除或替换事件处理器时，须覆盖旧路径承担的滚动、焦点、选择、返回导航与错误处理。经用户授权的产品变更以新验收要求为准，不得违背该意图保留过时行为。
3. **验证相邻失败场景。** 回归修复需要复现证据，外加对最可能被破坏的相邻场景的测试。共享逻辑变更需要预期场景与相关的反例；复用有效的既有测试。例如配额分类必须区分存储耗尽与文档数量耗尽。行为中性的复制或格式化变更可记录明确的不适用理由；不得虚构无关测试。既有 Harness TDD 要求不变。
4. **把原生桥接纳入契约。** 前端到 Android 插件的字段、枚举、资源集/数量与错误语义都是生产者/消费者契约。对真实生产者输出对消费者校验做测试，或提供同时基于两侧生产定义的、可复现的兼容性检查；断连的 mock 不充分。把共享错误码追溯到所有相关生产者含义与消费者映射，包括最终面向用户的 fallback。对独立版本发布的客户端，记录支持的版本组合以及是否需要更新客户端/包；不得为了掩盖不兼容而放松安全校验。
5. **证据与声称行为匹配。** 源码 regex 校验、构建、启动检查与 mock 单元测试只证明各自层。滚动、布局、焦点与原生交互需要对应的浏览器/设备/模拟器环境下的行为证据，自动化或可复现的手工均可。覆盖受影响的平台与模式分支，而非每一种平台组合。仅模式标签或数据集值变化并不构成执行两个分支。共享逻辑在代码证据与入口检查确凿建立实际连接时可复用测试；不同分支需要各自的证据。报告场景、环境、命令/步骤、观察结果与剩余缺口。模块启动如适用仍是独立的必需项，不属于交互测试。
6. **保留有意义的断言。** 删除或修改旧测试期望时，援引使其过时的授权需求变更或生产证据。仅做实现重构的必须保留等价的用户行为断言。不得仅为让测试变绿而削弱断言。已知错误行为是 FAIL；缺失必要证据是 PARTIAL / unverified（环境阻碍验证时为 blocked），绝不能判为 complete/PASS。测试数量与成功构建不能覆盖缺失的场景。

仅为适用面使用这份精简记录：

- 预期变更 / 保留行为 / 受影响的生产者、消费者、同级与平台路径。
- 场景 / 预期结果 / 证据层与环境 / 命令或步骤 / 观察结果。
- 相邻失败场景 / 变更断言的理由 / 兼容性与发布要求。
- 缺口与结论，或对行为中性变更给出明确的不适用理由。

历史案例按需补充并记录在本任务或 PR 中。

## 回归教训 guard（Regression lessons guard）

修复涉及业务资产、异步生成、重新生成/删除/保存流程、轮询、幂等、用量计量或日志噪音时，编辑前先建立必要习惯：先定义用户可见语义，再沿 `frontend -> backend(Java) -> 持久异步载体 -> 轮询` 追踪；核对同动作名的同级业务资产；除非明确指示否则保留既有数据；并从文档或 `.trae/tasks` 中移除过时或不一致的处理说明。
