# Harness 需求协作

读取时机：用户选择 Harness 后，需求澄清与确认前。仅加载本任务命中的规则；正文约束沿用原适用范围，不因读取而进入 Harness。

## 需求协作清单（Harness 拆分前必做）

澄清记录必须覆盖：问题/背景；用户/场景；预期结果；核心流程（含中断、撤销、重试）；输入/输出；状态与异常；约束；权衡偏好；决策权归属；验收标准与证据；已确认事实、假设、未知项；风险与后续范围。明确列出非目标（non-goals）。存在未能解决且可能实质改变实现的决策时，任务不得进入可拆分状态。

## 协作选项协议

每轮澄清使用如下结构：

```text
当前理解：
<AI 对需求的简要总结>

推荐方案：
<推荐选项及理由>

可选方案：
A. <option>
B. <option>
C. <option>

你也可以直接填写：
<允许用户补充或覆盖方案的提示>

当前待确认：
- <只有会改变范围、架构、体验、验收或风险的决策>
```

分阶段澄清：目标/问题/用户 → 预期结果/范围/非目标 → 核心流程/输入/输出 → 异常/状态/权限 → 约束/权衡 → 决策权/验收证据/风险/后续。每轮选择后记录推荐、选中项与自定义输入。用户说"按推荐方案"时，把采纳的推荐写入协作记录并请求最终确认。只对实质未知项追问；其它细节标记为 AI 自主决策或跳过的非关键问题。
