# Harness 需求协作

读取时机：用户选择 Harness 后，需求澄清与确认前。仅加载本任务命中的规则；正文约束沿用原适用范围，不因读取而进入 Harness。

## 需求协作清单（Harness 拆分前必做）

澄清记录必须覆盖：问题/背景；用户/场景；预期结果；核心流程（含中断、撤销、重试）；输入/输出；状态与异常；约束；权衡偏好；决策权归属；验收标准与证据；已确认事实、假设、未知项；风险与后续范围。明确列出非目标（non-goals）。存在未能解决且可能实质改变实现的决策时，任务不得进入可拆分状态。

## 协作选项协议

每轮澄清只向用户展示四块对话卡片；完整字段仍写入意图文件或任务文件，不在对话中重复：

```text
当前判断：<一句话总结当前已知事实和缺口>
建议：<推荐选项、理由、代价>
待你拍板：<最多一个实质决定；没有则写“无需拍板”>
下一步：<继续追问一个问题，或记录决定并进入下一段>
```

分阶段澄清仍按以下顺序推进：目标/问题/用户 → 预期结果/范围/非目标 → 核心流程/输入/输出 → 异常/状态/权限 → 约束/权衡 → 决策权/验收证据/风险/后续。每轮至多询问一个会改变范围、体验、架构或验收的问题；给出建议并记录用户选择与自定义输入。用户说“按推荐方案”即为该实质问题的决定：记录到协作记录后继续，不再请求对同一内容或摘要作第二次确认。只对实质未知项追问；其它细节由 AI 在确认范围内自主决定或标记为非关键问题。用户当前明确请求、已接受的 intent 或已确认规格可作为父 requirement 的确认来源；父任务是记录，不是额外审批关卡。
