# 资源安全与数据规模

## 适用场景

文件解析、引用映射、批处理、全量读取、数据转换、缓存或并发任务的实现与资源配置变更，在影响分析、设计、修改及资源行为验收前读取本规则。按实际行为和调用链判断；共享函数只改几行，也要检查它处理大数据时的影响。开发者与 AI、直接执行与 Harness 同样适用。

仅修改文案或格式且不影响上述行为时，在已有记录中说明具体不适用理由，沿用原有检查。规则材料自身修改验证路由、内容与证据引用；本规则不自动要求重跑未改变的业务压力测试。

## 必须遵守的要求

1. **先确定规模与预算。** 记录受影响输入的字节、页数、行数或对象数量，以及解析、解压、转换后的扩张维度。预算依据实际支持范围、活动配置、部署资源和测量，明确哪些是事实、估算或未知；不设置全项目统一的内存阈值，也不能把一个历史样本当作产品上限。缺少必要限额或测量时，不得宣称目标部署容量已验证。
2. **分析同时存活的对象。** 沿受影响路径识别原始输入、解码对象、转换副本、索引、结果缓冲和缓存的持有者与释放时机。检查循环中复制完整集合、分块后全量聚合、重复解码、缓存持续持有旧版本等放大因素。完整产物可随数据量合理增长；说明必要产物与额外工作集的差别，不强制所有处理绝对 O(1)，也不按 API 名称一概禁止全量读取。
3. **计算实际并发。** 确认 worker 进程或线程、每任务内部扇出、待执行/预取任务、跨请求缓存及多实例的资源边界。限制同时持有的大对象和待执行任务数量；只限制执行中的请求却预先创建全部任务或全部分片，需要证明其排队对象与数据持有量可控。
4. **验证释放与异常路径。** 根据实际影响覆盖正常结束、失败、取消、超时或重复执行的缓冲、连接、文件句柄和缓存释放。涉及强杀或跨实例恢复时，沿[共享状态规则](shared-state.md)核对共享租约、owner 和恢复路径；`finally` 不能证明进程被强杀后共享资源会回收。
5. **同时保护结果与资源。** 优化不能通过漏页、丢记录、截断引用或静默失败取得通过。改变输入准入、截断、超时或降级语义时，先核对已授权需求和[契约规则](contracts.md)，保持原有适用行为保护；资源优化本身不授权这些产品变更。

## 原理

- 流式接口只描述数据交付方式。下游执行全量收集，或缓存仍持有所有历史对象时，整体工作集仍随输入增长。局部变量重新赋值也不会释放被其他容器持有的旧对象。
- 若 N 个段在 K 次编辑中反复复制，且缓存保留各版本，额外工作集可能接近 O(N × K)。分批处理独立编辑、复用当前索引并释放旧版本，可以减少同时存活的副本；交叠编辑仍需保留正确顺序。详情见[引用转换复盘](../references/regression-cases.md#引用转换中的内存放大2026-10-09)。
- 容量初筛应分别核算进程基线、同时执行任务的工作集、共享缓存和预取开销，按线程/进程模型避免重复计算共享部分。并发增大可能放大峰值；估算不能代替目标配置下的测量。
- Python `tracemalloc` 记录受追踪的 Python 分配，RSS 是操作系统口径的进程驻留内存，容器限额与用量又有不同范围。三者不能互相替代；进程强杀、signal 9 或一次任务成功都不能单独证明是否发生 OOM、存在泄漏或容量充足。

## 正反例

| 场景 | 不足的方案或证据 | 应分析或验证的内容 |
|---|---|---|
| 引用转换 | 每次编辑都复制完整段列表，并缓存历次索引；小文档正确便判定完成 | 同时存活的版本数、大规模段与编辑数量、完整文本/偏移/页码/区域/来源/标识对照 |
| 分页或逐页读取 | 每页结果最终追加到总列表，仍宣称内存有界 | 结果必须全量保留的理由、额外副本、消费或输出窗口及峰值测量 |
| 缓存调整 | 只设置 TTL，未分析过期前的条目总量或单条大小 | 缓存容量、对象体积、替换/淘汰、重用与失效对正确性的影响；权威状态继续遵守共享状态规则 |
| 并发批处理 | 先创建全部任务和输入，再用信号量限制执行 | 执行与排队对象的持有量、有限窗口、取消/失败释放及实际并发峰值 |
| 资源优化 | 通过跳过末页或丢弃引用降低内存 | 原结果完整性与资源改善分别成立，适用相邻反例仍通过 |

## 验证入口

- 按实际影响复用有效的现有测试与压力脚本，覆盖正常输入、大规模输入、适用的并发或重复执行，以及失败释放场景；不同规模用于检查增长趋势，不要求无关任务执行全栈压力测试。
- 记录样本构造与规模、代码版本、运行环境、实际并发/预取/缓存配置、可获得的资源限额、测量口径、命令及观察结果。判断容量或资源改善时，阈值依据目标配置或已约定的基线；构建、mock 和源码检查只证明各自层级。
- 引用相关改动可沿[复盘中的现有验证入口](../references/regression-cases.md#验证入口与证据边界)执行完整结果与资源对照。当前测量与历史报告分开记录，历史结果不能作为本次通过证据。
- 已知结果错误或资源要求不满足按[防回归规则](regression.md)判为 FAIL；必要验证缺失保留 PARTIAL / 未验证。依照[文档一致性规则](documentation.md)同步实际受影响的描述与证据。
