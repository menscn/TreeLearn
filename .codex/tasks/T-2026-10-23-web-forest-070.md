## Requirement collaboration brief

- Parent summary：父卡 038 登记用户 2026-10-23「按 harness 开发，web 和 android」授权；森林规格 `Docs/spec/SPEC-2026-10-21-my-forest.md` 与斜俯瞰原型 04/05 屏对两端同时生效。Android 侧已在 068 落地（`ForestLayout` 纯函数 + 自绘树精灵 + 四态页），本片只做 Web。
- Problem/background: Web 工作区没有森林视图（`frontend/src` 扫 `forest|森林` 零命中）；父卡要求 Web 同步交付森林，且明确「Web 是只读 parity 演示，不伪造连续天数或生成数据」。
- Users/scenarios: 学习者在侧栏点「我的森林」进入全屏林地：一题一树、斜俯瞰、树干落地；点一棵树读到它的段枝数与当前人设，点纸条箭头回到该主题对话。
- Expected outcome: 侧栏出现森林入口；`forest` 视图渲染斜俯瞰地块（等高线、草簇、点阵地面）与每棵树的树干/树冠/落地影；树位置由主题 id 稳定决定（与 Android `ForestLayout` 同常量同算法）；点树出现光晕、地面圈、标题胶囊与底部纸条；页脚只写本次真实读到的数字。
- Core flow and reversibility: 侧栏入口 → `openView("forest")` → `ForestPage` 读 `WorkspaceDataProvider` 的 topics 与 069 的会话内人设映射 → `forestLayout` 纯函数算归一化坐标 → SVG 渲染；点树只改选中；纸条箭头 `openTopic(index)`；返回走既有 `back()`。森林不写任何状态、不改夹具。
- Inputs/outputs: 输入是 `workspaceData.topics`（title、branchCount 可为 null、meta）与 `store/workspace` 的人设映射；输出是一屏 SVG 林地、选中纸条与诚实页脚。
- State and exception handling: 数据 `loading` 与全局 `error` 由 `WorkspaceRouter` 的共享状态行统一挡门（森林不另加永不渲染的 loading 文案，见 AI-autonomous decisions ⑤）；topics 为空显示空态 + 「去种第一棵树」回首页；学习库整屏读不到（`partial` 且零主题）显示「森林暂时读不到」+ 说明（Web 无重试入口时不画假按钮，见 AI-autonomous decisions ③）；某主题 branchCount 为 null 时该树按 1 段枝画、页脚省略段枝总数；归档数与连续天数在 Web 读不到，页脚一律省略，不写 0 冒充。
- Constraints and trade-offs: 布局常量与算法逐值对齐 Android `ForestLayout`（FNV-1a、黄金角、密度修正、尺寸上下限 0.0685/0.1269、9 段枝封顶、tone 0.80..1.15、seed=hash&0x7fffffff），两端差异只在渲染介质；SVG 填色只走 CSS 类引 token 变量；文案走 copy；可点区域不小于 44px；不新增依赖。
- AI recommendation and rationale: 布局做成 `store/forestLayout.ts` 纯函数并用 vitest 钉住「同 id 同位置、顺序无关、上限收敛」，与 Android `ForestLayoutTest` 同判据；树精灵用 mulberry32 的 TS 移植生成 SVG 图元，保证同一 seed 在两端形状同族。
- User choice and custom additions: 斜俯瞰、能看到树干；位置固定不随最近学习重排；归档子树口径在 Web 无数据来源，按「读不到就省略」处理，不虚构。
- AI-autonomous decisions: ① 侧栏入口放在主导航与「最近学习」之间的一张入口卡（图标 + 主副文案 + 箭头），对应 Android 抽屉入口的语义位；② 纸条元信息只显示「N 段枝 · 当前档名」：Web 没有结构化最近学习时间戳，夹具 meta 里的时间文案是采集时刻的字符串，搬进纸条会把过期时间当现状，故省略；③ 错误态不画「重试」按钮——`WorkspaceDataProvider` 未暴露重读入口，画一个不生效的按钮比省略更不诚实，错误说明文案保留；④ 场景用单个 SVG + viewBox 归一化坐标，命中区用透明 circle 保证 >=44px；⑤ loading 与全局 error 由 `WorkspaceRouter` 共享状态行挡门，森林不新增 `forest_loading` 键——该文案在任何路径都不会渲染，死文案比省略更不诚实，验收第 6 条据此改述（改述理由见 Verification report）；⑥ 标题胶囊默认贴在树脚下方，当另一棵树占据「正下方邻带」（dy∈(0,0.22) 且 dx<0.30）时翻到树冠上方，避免胶囊悬在两棵竖邻树之间归属不明（设计师复核缺陷 2 的修法）；⑦ Web 主题 id 由夹具下标派生（`topic-${index}`），没有真实 UUID，故与 Android 的 parity 判据是「同常量同算法」（两端单测各自钉住同一组判据），不是同名 id 同坐标。
- User-confirmation decisions: 本片不新增需要用户拍板的产品决策。
- Acceptance evidence: `forestLayout` 与 `ForestPage` 的 vitest 用例；`pnpm test`、`pnpm lint`、`pnpm build` 全绿；浏览器截图走通侧栏入口→林地→点树→纸条箭头进入主题→返回。

## Implementation notes

- `store/forestLayout.ts` 是 Android `ForestLayout.java` 的纯函数移植：FNV-1a（`0x811C9DC5` / `Math.imul(h,0x01000193)`）、黄金角 2.399963229728653、中心 (0.50,0.465)、半径 (0.40,0.335)、边界 X 0.10–0.90 / Y 0.13–0.80、count==1/2 特例、angleJitter/radialScale/rho、count>18 时 40 轮 MIN_GAP 0.048 分离、尺寸 9 段封顶 0.0685–0.1269 × 密度、tone 0.80–1.15、seed `h&0x7fffffff` 归零改 1、branchCount null 按 1；长度不匹配与 null id 抛错。
- `ForestScene.tsx` 用 ResizeObserver 量容器盒，使 viewBox 单位等于 CSS px（jsdom/首帧回落 1000×620），于是「命中区 >=44px」在浏览器里可实测（probe 读得窄屏 52px/47px）；地形分数（等高线基线、草簇、石块、土丘两点闭包）取自 Android `ForestScene.buildTerrain`；树精灵是 `ForestTreeSprite` 的 mulberry32 TS 移植；SVG 填色一律走 `.fs-*` CSS 类引 token 变量，选中光晕用 `<radialGradient id="forest-halo">` + 类化 stop。
- 标题胶囊默认贴树脚（`translate(-50%,0)`），下方邻带被另一棵树占据（dy∈(0,0.22) 且 dx<0.30）时翻到树冠上方（`.forest-tag.above` = `translate(-50%,-100%)`）；胶囊 x 夹在 [0.14w,0.86w]、top 夹在 [8,h-8]。
- 纸条 meta = 段枝（null 省略）+ 当前人设档名，用 `forest_meta_separator` 连接；页脚 = 树数恒有 + 段枝总数（仅当全部 branchCount 已知）；归档与连续天数永不出现。
- 空/错分开：`groundReadable = status==="ready" || topics.length>0`；整屏读不到（partial 且零主题）出错误态且无按钮，ready 且零主题出空态 + 回首页 CTA。
- 刻意不新增的 copy 键：`forest_loading`（路由挡门）、`cd_forest_back`（壳顶栏已有返回）、`forest_error_action`（无重读入口）、`cd_forest_open`、`forest_meta_archived`、`forest_foot_archived`、`forest_foot_streak`（Web 无数据源）。
- 壳层改动四处同改：`WorkspaceView` 联合、`VIEWS`、`WorkspaceRouter` 分发、`AppShell` 入口卡与面包屑；入口卡位于 `</nav>` 与「最近学习」标题之间，窄栏折叠时隐藏主副文案只留图标。
