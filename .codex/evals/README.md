# Treelearn 评测集（`.codex/evals/`）

> 这里放的是「AI 产物 vs 基线期望」的可重跑判定。规则、角色正文、守门脚本各有只读守门，
> 本目录补的是最后一块：产物本身变差了要有一条命令能响，而不是靠人再读一遍。

## 跑法

一条命令，从仓库根或任意目录都可以照抄：

```text
python -X utf8 .codex/scripts/run_evals.py
```

退出码 0 = 全部期望成立；1 = 至少一条 FAIL。它已登记进 `.codex/scripts/run_all_guards.py`
的 core 档，所以每片的整跑里都带着它。

## 一个 case 长什么样

`.codex/evals/cases/<编号>-<kebab-name>/` 三件套，缺一不可（缺任一份该 case 直接 FAIL，
不会静默跳过）：

| 文件 | 作用 |
|---|---|
| `input.md` | 当初派给角色的任务，以及产物的来源与转录说明（谁产的、哪一天、改动列在哪） |
| `expected.md` | 基线期望：每行一条 `- <形状>: <载荷> >= <阈值>`，判的是 `product.md` |
| `product.md` | 那份 AI 产物的逐字快照（不是活文件，见下） |

## 期望的五种形状

| 形状 | 判什么 | 为什么会坏 |
|---|---|---|
| `must: <词> >= N` | 含该词的逻辑条目数 >= N | 该字段被删空或改写掉了关键词 |
| `shape: A & B >= N` | 同一条目里同时含 A、B 的条目数 >= N | 结论只剩措辞、只剩指针、或只剩「不适用」而不给理由 |
| `forbid: <词>` | 含该词的条目数为 0 | 占位符或猜测语气混进产物 |
| `pointers-alive >= N` | 产物里 `路径:行` 引用数 >= N，且每条都能在**当前工作树**复算（文件在场、行号不越过文件末尾） | 被引用的实现被删/搬/缩短，而产物还留着旧指针 |
| `paths-exist >= N` | 产物引用的仓库相对路径数 >= N，且全部在场 | 引用裸文件名或写死一个不存在的路径 |

逻辑条目 = bullet 连同它的续行（一条 bullet 换行成三行不该改变判据读数）。
正向期望（`must` / `shape`）另受一条结构规矩约束：产物的每条 bullet 至少要被一条正向期望钉住，
所以「顺手删掉一条期望」必然让某个条目失钉而转红。

## 快照与活文件的分工

`product.md` 是快照：它不动，产物变差了才看得出来。它内部的两类判据
（`pointers-alive`、`paths-exist`）始终对着**当前工作树**复算，因此快照不会变成一段回忆——
被引用的代码删掉了，这里就红。重新转录一份快照的步骤写在对应 case 的 `input.md` 里。

## 这里不判什么

角色契约、`.toml` 与 `.md` 是否同源、评测目录是否被 README 登记，都由
`.codex/scripts/check_eval_keeper_agent.py` 判（ROADMAP B2）。两边判据不重叠，
否则改一句措辞要同时红两支脚本。
