# 首页视觉还原规格（高保真原型 → Android APK）

## 需求规格

- **目标**：把 `Docs/04-ux-design/知芽-TreeLearn-高保真原型-v1.html` 的**首页**视觉语法 1:1 落到 Android 生产界面（字体、背景、纸感纹理、按钮与胶囊样式、卡片、间距、圆角、阴影、动效）。
- **用户/场景**：单人自用。用户打开 App 落在首页，看到的是与原型一致的纸感首页，而不是当前的通用 Material 卡面。
- **范围边界**：
  - 只做**首页**。学习库、设置、对话、画布、导航页本次不改版式；它们与首页共用的 drawable 本次不动（见技术规格的「共享资源冻结」）。
  - 底栏三标签（主页 / 学习库 / 设置）与首页左上抽屉按钮**保留**（原型的 Android 框内没有这两件，属本项目外壳，不在还原对象内）。
  - **信息架构按 V3.2 保持**：首页不加搜索与归档入口（搜索唯一正典入口是学习库顶部搜索框、归档归学习库），主题卡不加「⋯」改名/删除菜单，首页主题区仍是「最近若干条」的快捷面而非全量列表。
- **已确认决策（用户 2026-09-27）**：
  1. 视觉 1:1、IA 保持 V3.2（上条）。
  2. 字体走**系统 sans-serif（正文）+ 平台衬线（品牌与标题）**，不打包任何字体文件；原型 `:root` 亦已注明 Android 落系统 sans-serif。
  3. 本需求走 Harness 流程。
  4. **版式顺序以本规格为准**（见「界面方案」首条）。
- **与既有规格的关系（裁决，不复制正文）**：`Docs/spec/SPEC-2026-09-27-home-drawer-ux.md` 的首页顺序条（推荐区在输入框之上）自本规格起**被取代**：首页自上而下改为「品牌锁定区 → 主标语 → 输入卡 → 推荐区 → 历史主题」。该文件的对应条目由本轮实现任务添加一句指针，不复制本规格正文（遵循「一条规则唯一正文出处」）。
- **与 2026-09-27 评审 M 批次的边界**（`Docs/04a-ux-cross-review/知芽-TRELEARN-PRD截图对齐分析_2026-09-27.md`）：
  - **并入本轮**：M7（推荐区标签补齐「入门 / 顺着你学的 / 换个方向」与「就绪」文案动态化）落在推荐区任务；M11（发送控件禁用态对比度复核）落在输入卡任务。
  - **不纳入**：M3（首页新增迷你热力条，原型首页也没有，属新增内容）；M8（全站顶栏安全区内边距，要求所有页面统一，属另一条工作线）。
- **非目标**：不做暗色主题；不引入新依赖与新字体包；不改设计 token 数值；不改 theme 之外的全站样式；不实现原型的 hover 态（换成 Android 按压反馈）。
- **验收证据**：构建与 lint、Java-only 守门、设计 token 守门、首页相关仪器测试、首页两态截图，逐项落 `artifacts/evidence/`。

## 界面方案

**版式顺序（自上而下，滚动页从顶部自然排布，不再垂直居中）**

1. 顶栏：左侧抽屉按钮；原型的「搜索 / 归档 / 设置」三图标按上文裁决**不搬**。
2. 品牌锁定区：幼苗标记与「知芽」**横排**居中（品牌色幼苗 ＋ 衬线粗体品牌名），下留一档间距。
3. 主标语：衬线标题，**仅在没有历史主题时出现**，居中。
4. 输入卡：卡面承载输入框与底部一行控件；输入框内为**信纸横格**（浅绿细线），行高与格距对齐原型；底行左为模型标识胶囊（思考态追加标记），中为 Key 提示胶囊，右为圆形发送按钮（禁用态为中性灰）。
5. 推荐区：头部为「✦ ＋ 短标签」，两条独立轨道反向横向滚动；每张卡片为「左侧类别胶囊 ＋ 文本 ＋ 右侧箭头」，类别胶囊分三档（入门 / 顺着你学的为品牌淡底，换个方向为中性淡底）。
6. 历史主题：区头为「13 号档标题 ＋ 计数」；其下为卡片列。每张卡片含：未读蓝点（有才画）、衬线标题、两行截断摘要、元信息行（树图标＋分支数、相对时间、可选「临时标题」胶囊）；整卡可点。无主题时显示空态文案，不显示计数器。

**整页背景**：纸感横格 —— 全屏每行高一档画一条极淡横线，读作纹理而非参考线；输入卡内的信纸格线是同一画线规则的浅绿变体。

**矩阵勘误（2026-09-27，执行 003 时核对原型发现）**

- 原矩阵把 `.home-input textarea` 的行高记作 `--lh-read`，与原型不符。原型第 153 行该 textarea 的实际声明里，`line-height` 与它的格线周期取的是**同一个值**（数值见原型原文，本规格不复制数值），该值恰等于 `space_s8`，也就是与整页纸纹的周期同值；`--lh-read`（原型第 74 行）是给阅读正文用的，两者不要混用。已按原型改正本行的取值来源。
- 结论：输入框信纸格线与整页纸纹的**线距相位完全相同**（首线顶边与周期同值），只有颜色不同（`--paper-write` ↔ `--paper-rule`）。因此 004 自绘格线时直接复用 `PaperRules.lineOffsets(...)`，只需换派生色；不要为输入框另写一套线距。

**与原型的有意偏差**（可核查、逐条有理由）

| 偏差 | 理由 |
| :--- | :--- |
| 不做 hover 态 | 触屏无 hover；改接按压反馈 |
| 类别胶囊/推荐卡高度按 `touch_min` | 项目规则要求可点区域不小于 44dp；原型实际高度更小 |
| 首页顶栏保留左上抽屉按钮 | 本项目外壳；原型没有该入口 |
| 不搬顶栏搜索/归档图标、不搬主题卡「⋯」菜单 | 与 V3.2 的信息架构裁决冲突（见需求规格） |
| 空态不提供「先逛逛示例主题」 | App 无示例数据生成器，不做仅用于演示的假数据 |
| 品牌字形按平台衬线 | 不打包字体（已确认决策） |

## 技术规格

- **修改面（按文件归属切分，避免并行编辑冲突）**：
  - `android/app/src/main/res/layout/screen_home_body.xml`（版式顺序、各区块视觉）
  - `android/app/src/main/res/layout/screen_home.xml` 与 `layout-sw600dp/screen_home.xml`（整页纹理层接入）
  - `android/app/src/main/java/com/treelearn/app/screen/HomeScreen.java`（按 ViewState 绘制、卡片与空态、动效错峰）
  - `android/app/src/main/java/com/treelearn/app/screen/RecommendationMarquee.java`（卡片重排后的绑定）
  - `android/app/src/main/java/com/treelearn/app/MainActivity.java`（换屏入场动效，仅首页相关路径）
  - 新增资源：整页纹理装饰 View、自绘输入框、幼苗/钥匙/星芒/箭头矢量、卡片与发送按钮形状、历史主题卡布局、首页专属字符串
  - `android/app/src/main/res/values/strings.xml`（主标语去换行、区头改「历史主题」、元信息格式串、空态文案、「就绪」文案动态化）
- **唯一实现约束（对应本仓失败案例库）**：整页纹理与输入框信纸格线共用**同一个画线实现**（同一处计算线距与颜色），不得写两份画线逻辑；纹理色与信纸色以既有 token 派生，推导落在该唯一实现的注释里并标注原型出处行号，不新增 token、不改 `tokens.json` 与 `colors.xml`。
- **共享资源冻结**：`bg_card` / `bg_pill` / `bg_chip` / `bg_field` / `bg_button_primary` 全站共用，本次**不改**；首页需要与它们不同的形状时新增首页专属资源。由此产生的「首页专属与全站共享并存」记入 Deferred，后续统一收敛。
- **装饰层约束**：纹理层为纯装饰，不可点、不可聚焦、对无障碍隐藏，且不得拦截抽屉与滚动手势（沿用画布圆点装饰层的既有做法）。
- **平板**：沿用现有 `content_measure` 列宽与 `page_gutter` 覆盖值，纹理层同样覆盖。
- **契约保持**：被仪器测试断言的首页 id（输入框、历史主题列表容器）必须保持存在且语义不变，历史主题列表在有数据时仍必须可点进入对话。顺序调整后需复跑相关仪器测试。
- **文档同步**（与代码同批落地，不提前改）：`Docs/spec/SPEC-2026-09-27-home-drawer-ux.md` 加顺序取代指针；`android/README.md` 首页一节回写新增装饰层、新资源、版式顺序与动效；PRD 不动（不涉信息架构）。

## 疑虑点

- **首屏留白**：2026-09-27 评审的 P0-3 指出首页首屏大面积为空。本次改为自上而下自然排布并移入输入卡与推荐区，方向上是缓解；但若历史主题为空、推荐区也拿到空列表，首屏仍会偏空——这属数据面而非视觉面，需在真机截图确认后决定是否另立条目。
- **顺序变更的回归面**：首页版式顺序被改动，且部分首页行为被仪器测试断言；顺序相关断言可能需要同步调整，属于本轮的必须验证项。
- **字体字形差异**：平台衬线在不同 ROM 上字形不同，品牌锁定区的观感会有轻微差异；这是「不打包字体」决策的已知代价，若用户后续要求逐像素一致，需另立「包字体」条目。
- **共享资源并存**：本次不收敛全站 drawable，首页与其它页面在同一设计语言下会出现两套形状资源；若后续全站统一，需要一次独立的收敛任务。
- **M3 的排期**：首页迷你热力条（评审 M3）与本规格同处首页顶部区域，若两条工作线并行落地，会争抢同一区块的排布；建议在实现首页视觉时保持顶部区块留有扩展位，M3 单独排期。
