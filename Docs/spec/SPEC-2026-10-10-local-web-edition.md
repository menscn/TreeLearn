## Requirement spec（需求规格）

- 目标：电脑启动本机服务后通过 localhost 进入真实 Web 产品；两端数据独立，业务功能与活动 Android 实现对齐，交互适配键盘、鼠标和大屏。
- 本轮产物：[HTML 原型](../04-ux-design/知芽-Web本地版-交互原型-V0.1.html)、[功能对照](../05-technical-design/TreeLearn_Web本地版_功能一致性矩阵.md)、[开发方案](../05-technical-design/TreeLearn_Web本地版_详细开发方案_V1.0.md)及 AI 交接入口。
- 已确认：A「专注阅读」默认；两端不同步；薄荷雾面 Web 配色；图标来自 [v1.1 原型](../04-ux-design/知芽-TreeLearn-高保真原型-v1.1.html)。其它页面细节作为 review 稿，不把每个模拟行为当生产事实。
- 功能覆盖：主题/分支、生成与恢复、回答版本、思考、上下文压缩、引用/复制/推荐追问、富内容、高亮批注、翻译朗读、语音草稿、应用内/联网搜索、Provider/模型、附件/文件、归档恢复删除、未读/阅读位置、学习统计、设置。
- 非目标：同步、账户、公网/局域网使用、云存储、Android UI 迁移、自定义 Agent 平台、未经生产核对的新协议、新人设选择器或新文件格式。
- 来源：[新意图](../intent/INTENT-2026-10-10-local-web-edition.md)的 Expected outcome、Core flow、Constraints and non-goals；功能事实见对照矩阵的活动来源。

## Interface plan（界面方案）

### 信息结构与布局

- 外壳：左侧常驻导航（主页、学习库、树总览、学习足迹）与最近主题；设置为底部辅助入口。窄窗口折叠为可关闭的导航抽屉；不把手机底部双入口照搬为桌面任务栏。
- A 默认：对话正文单列居中，阅读宽度受限以避免过长行；右侧学习脉络按需打开，含分支、来源、批注。打开侧栏后保持草稿与阅读位置；关闭后正文重新居中。
- B：当前对话与来源/选定分支并排；两栏独立滚动，当前输入明确归属当前分支。需要对照时切入，窄屏回退到单列。
- C：在当前对话旁展示树图；大树可展开完整总览，点击节点进入分支。节点不能自由改连线或重挂父节点。
- 配色权威：[Web token 文件](../04-ux-design/web-local-design-tokens.json)依用户新配色建立 Web 命名空间；基础间距、圆角、字体、阅读行高继续引用现有 `s*`、`r-*`、`fs-*`、`lh-read`。图标保留 v1.1 的轮廓与描边。
- Web 色名：`web-white`（内容）、`web-mist`（雾面底）、`web-mint`（选择/柔和状态）、`web-sage`（主操作/边界）、`web-on-sage`（主操作可读文字）。色值集中在 token 文件，不在规格里另存第二份。

### 页面与流程

| 页面 | 用户动作与反馈 |
|---|---|
| 主页 | 输入首问、选择模型、开始主题；无 Key 引导到原路可返回的配置页，不留下空主题；最近学习继续到保存的分支与位置。 |
| 学习库 | 学习中/归档切换，搜索主题/分支/消息；结果定位来源回答；归档子树整体恢复，删除先显示范围并确认。 |
| 对话 | 标题、来源面包屑、用户问题、推理折叠、回答与动作行；引用行和附件行可单独移除，不丢草稿；生成中发送位切换停止。 |
| 分叉 | 整条稳定回答或稳定版本内选文触发；编辑名称与首问后创建；原分支状态、草稿与阅读位置保留；推荐问题的普通追问与分叉是两个不同动作。 |
| 批注 | 选文浮条含复制、引用、分叉、高亮、批注；高亮可点击编辑；批注侧栏回到对应回答容器与版本，不用 DOM 路径作持久锚点。 |
| 树总览 | 平移、缩放、定位当前节点、适应视口、折叠/展开、键盘进入；未读聚合与归档隐藏来自服务快照。 |
| 设置 | Provider 编辑与 Key、模型三分工与预算/建议、联网搜索、语音、文件和 Web 输入偏好；设置返回原入口，缺 Key 引导返回原草稿。 |
| 文件管理 | 文件名/格式/大小/解析与物理存在状态/引用数；支持有确认的删除与孤儿清理；删除正文后引用保留缺失标记。 |
| 学习足迹 | 沿用真实统计口径，热力日期与阅读时间统一通过设备时区显示；原型标注示例统计。 |

### 输入、滚动与状态

- 键盘：默认 Enter 发送、Shift + Enter 换行；可选择 Ctrl + Enter 发送。输入法组合期间不发送，Enter 再次确认候选不误触。Ctrl/Cmd + K 打开学习库搜索。
- 鼠标：选文出现靠近选区且不越出视口的浮条；点操作时选区保持；行内代码、公式与表格容器映射必须单独验证；没有悬停也有可操作入口。
- 生成：跟随最新、用户上翻暂停、回到最新、完成稳定状态分明。停止保留部分回答，失败提供原位重试；部分回答不可分叉，流式刷新不抢焦点或选区。
- 重建：浏览器刷新读快照后恢复显示，不重发上一条命令；服务退出不丢已提交记录；来源面板、草稿和阅读位置的保存层不得只依赖页面内存。
- 语音：麦克风授权拒绝、不支持、识别失败均可回到文字输入；识别文本追加草稿，不自动发送。朗读的开始/停止有明确状态。
- 错误：可读、可行动的本地化提示，不展示 Java/网络库原始错误。配置回落与请求失败换模型是不同情况，前者按既有规则提示，后者不暗中切换。
- 来源：`ChatActions`、`ChatPresenter`、`LibraryPresenter`、`NavigationPresenter`、`TreeCanvasPresenter`、`Annotation`、`MainActivity`、现行 2026-10-09 设置入口决定；详见功能矩阵。

## Technical spec（技术规格）

- 分层：React 页面 → 用例/RuntimeAdapter → 本机同源 API/SSE → Java 应用用例 → 领域规则/Repository/AI Gateway；系统凭据、桌面 SQLite、文件与语音为平台适配能力。
- 共享：优先以同一构件复用 `:core` 与 `:tree-layout`；AI 装配和生成协调不能直接搬用 Android API。共享抽取必须证明 Android 回归，而不是仅让桌面编译通过。
- 数据：服务端本机持久化为 Web 状态权威；浏览器只保存非敏感 UI 偏好或可恢复缓存。SQLite 的表清单以活动 `TreeLearnSchema` 为对照，桌面表准入和真实引擎迁移证据在开发时完成。
- 生成：持久 operation identity；首主题原子接受、单分支并发限制、正常终止且非空才稳定、不可变回答版本与分支创建快照；取消/失败/中断区别不被 UI 合并。
- 事件：正式 API/SSE 单一契约在开发前定稿，定义快照版本与事件顺序、缺口恢复、重复提交、取消与终态。此规格不充当另一份协议正文。
- 文本锚点：复用 `Annotation.Container/Locator/Span`、内容 digest 与当前 DAO 的有效性规则；Java/JS 的区间采用确定的编码单位；跨容器选文不混成一个坐标。
- 凭据：用户录入仅经本机接口发送给凭据适配，后续查询返回脱敏状态；禁止 API Key 进入 localStorage、SQLite 明文、日志、URL、SSE 与模型可见上下文。
- 依赖：候选版本需后续核对许可证、Node/Java/驱动兼容与锁文件；本轮不声称运行、性能或安全验证完成。工程细节、验证入口、顺序与疑难处理见开发方案。
- 来源：`web/shared/domain/build.gradle`、`web/shared/tree-layout/build.gradle`（原 `android/core`、`android/tree-layout`，2026-10-10 迁移并由两端 projectDir 引用）、`android/ai/build.gradle`、`GenerationCoordinator`、`TreeLearnSchema`、`KeystoreSecretStore`、`AppContainer`；治理依据各专项 rules。

## Doubts（疑虑点）

- 本机 SQLite 服务与旧后端 MySQL 默认、共享状态/遥测适用范围不同。建议按仅 loopback、单实例、本机权威存储写明确适用记录；若改为远程服务，应重新设计为对应服务治理，不能保留桌面例外。下游架构实现者负责核对规则，用户确认永久表准入；不通过目录命名绕开规则。
- 历史文档称内置人设已交付，但本轮对活动设置入口与生产源码未核到人设选择器；Web 保留既有教学提示词，不从原型或旧任务状态推导新选择器。后续如找到真实可达入口，补入功能矩阵，并同步两端范围。
- 浏览器语音识别不能假定等同 Android 系统服务；先验证目标浏览器的能力、权限、网络归属，再确定适配。不得把不支持时隐藏按钮作为功能一致验收。
- Web 使用用户指定的独立配色命名空间；Android 旧 token 权威继续服务既有消费者。本轮色值变更是用户明确授权的 Web 设计范围，开发不得自行改写 Android 颜色或把两套色值混成一套失去归属的清单。
- 新服务、驱动和凭据适配尚无运行证据；依赖清单、桌面表准入与真实 Provider/语音验收必须由开发阶段产出。原型与本规格的轻量检查只验证设计交付。
