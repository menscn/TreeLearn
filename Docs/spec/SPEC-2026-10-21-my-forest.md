## Requirement spec（需求规格）

- 范围：抽屉扩展位新增「我的森林」入口，进入独立全屏页。每个主题是一棵树，树的位置固定、不按最近学习重排；一棵树的段枝数等于该主题的分支数（含归档分支）。点树先选中并在底部纸条上显示这棵树的事实，再点纸条上的箭头进入该主题。统计复用既有口径，不新增指标；零 schema 变更。
- 预期效果：给「回头看自己种了多少树」一个可观赏的形态，情绪价值优先于信息密度；找回主题的正典路径仍是首页与学习库，森林只是抽屉里的快捷回顾入口，不取代它们。
- 验收方向：
  - 可机械验证：森林的主题集合与 `LibraryWiring.topics()` 同源；每棵树的段枝数来自同一条只读查询；归档分支计入树的段枝数并在纸条上显式标注；空态与错误态各有渲染路径；统计脚注读 `HomeStore.StatsRaw` + `StatsAggregator`，没有第二套口径。
  - 需人工体验：斜俯瞰的「森林感」、树冠疏密与绿色层次、选中反馈是否清楚；由用户真机验收。
  - 导航：从抽屉进入森林，从森林返回首页；点树进入主题后走既有主题打开路径，返回仍回到原来的主题内位置。
- 与归档口径的关系：BASE-14 的「归档隐藏」收窄为常规导航与列表，不含森林回顾视图。森林里不出现「归档主题」这个对象——产品里只有「主题内的归档子树」；每棵树都完整包含自己的归档子树，样式不弱化，只在纸条与统计脚注里以文字说明。
- 约束：Java-only；自绘 View + XML；视觉只引 token；可点区域不小于 44×44 dp；森林页不提供归档、删除、重命名等管理动作。
- 非目标：不做分享、导出、3D、缩放画布、复杂动效；不新增统计指标；不新增 schema；不改首页排序与总览画布的归档过滤；不做「自习室」等社交形态。

## Interface plan（界面方案）

- 抽屉入口：位于热力图卡之后、最近学习之前。一行 44 dp 高的可点区域：左侧圆底森林图标，主文案「我的森林」，副文案「全部主题长成一片林子」，右侧箭头。它是快捷入口，不改变学习库的主题列表地位。
- 森林页骨架：顶栏（返回按钮 + 主标题「我的森林」+ 副标题「一题一树，慢慢长」）；其下是铺满剩余高度的场景区；场景左上角一枚提示胶囊「点一棵树看看」，右上角一枚罗盘装饰；底部是选中树的纸条与一行统计脚注。
- 场景：斜俯瞰 3/4 视角，不是垂直俯视。每棵树由地面投影、落地树干、两根枝杈、若干树冠叶簇与左上高光组成；树冠在上、树干向下落地，影子落在右下。地面用三层绿色径向渐变加极淡的点阵与等高线，营造一块地块而不是一张白纸。
- 位置：每个主题的场景坐标由主题 id 稳定决定，同一次安装内不随学习时间、选中状态或列表顺序变化；树的大小由分支数映射到上下限之间，同一棵树在两次打开时大小一致。主题数量在自用规模（几十棵）内不引入缩放或平移手势。
- 选中：点树即选中，被选中的树出现柔光晕与地面圈，树上方（靠顶部时改为下方）出现标题胶囊；底部纸条显示标题、段枝数、最近学习时间、当前人设，以及「含 N 段已归档」；纸条右侧是 44 dp 的圆形箭头按钮，点它进入主题。点另一棵树只切换选中，不跳转。
- 统计脚注：一行小字，只显示本次真实读到的数字，例如「12 棵树 · 60 段枝 · 1 段已归档 · 连续 3 天」。任何一个数读不到就不显示该项，不写 0 冒充有数据。连续天数来自既有 `StatsAggregator`，不在这里另算。
- 状态：
  - 加载：场景中央一条纸色提示「正在数你的树」。
  - 空：无主题时，场景换成空地块插画 + 「去种第一棵树」按钮，按钮回首页的创建主题入口。
  - 错误：数据库读取失败时显示「森林暂时读不到」+「重试」，不崩溃、不影响抽屉其他功能。
  - 归档：不出独立状态；归档子树计入树形与段枝数，纸条文字说明。
- 尺寸与样式：页面底 `bg`、卡片与纸条 `surface`、描边 `line`、正文 `ink`、次要 `ink2`、弱化 `ink3`；树冠用 `green` 与 `green-soft`、树干与影子用 `green-deep`、地面用 `green-faint` 与 `green-soft`；圆角用 `r-md`（纸条）、`r-full`（胶囊与箭头）；阴影只用 `sh-1` 与 `sh-2`。所有数值来自 `Docs/04-ux-design/design-system/tokens.json` 生成的 Android 资源，不在代码里另写颜色。
- Web 对应：同一信息架构与同一套树精灵几何；场景用 SVG 绘制。Web 是只读 parity 演示，没有真实统计与生成数据时，脚注只显示可由 fixture 证明的「树数 · 段枝数」，不显示连续天数，也不伪造归档数。

## Technical spec（技术规格）

### 数据与口径

- 主题集合：复用 `android/app/src/main/java/com/treelearn/app/wiring/LibraryWiring.java:52` 的 `topics()`，不新写主题查询；森林不参与首页排序，只在场景里按稳定坐标摆放。
- 每棵树的段枝数：在 `:data` 新增一条只读查询，按主题聚合分支总数与其中归档分支数。它是既有分支表的投影，不是新统计口径：与总览画布、学习库读同一批行；查询只返回 `topicId / branchCount / archivedCount / lastVisitedAt` 四个值，不写库、不建索引、不改 schema。
- 统计脚注：复用 `HomeStore.StatsRaw` + `StatsAggregator` 的既有入口（与 `android/app/src/main/java/com/treelearn/app/ui/StatsDetailPresenter.java:13` 同一路径）；森林不直接查统计表，也不在 UI 层重新定义连续天数。
- 主题行的人设：森林纸条显示当前主题人设，读 `topics.persona`；未知值沿用主题读取的回落边界（见人设规格），不在森林里另写一套回退。
- 时间展示：最近学习时间走既有共享时间格式化，不在森林里另写相对时间。
- 深度读取：森林只读主题、分支与统计，不读取回答正文、不触发任何生成、不写任何表。
- 主题数量：自用规模按几十棵设计；一次读取全部主题的分支计数，不做分页。若未来规模上万，另开需求决定聚合缓存，本规格不预支。

### 布局与绘制

- 森林的场景摆放不是第二套分支树布局：`TreeLayout` 画的是「一个主题内的分支树」，森林画的是「主题与主题之间的地块」。intent 的「不为森林新写一套树布局」指前者；森林不调用 `TreeLayout`，也不修改它。
- 场景坐标：新增纯函数 `ForestLayout`（JVM 可测），输入主题 id 与分支数，输出归一化坐标、树大小与叶簇种子。坐标用主题 id 的稳定散列加黄金角散布，并做最小间距修正；同一 id 在任何一次启动都得到同一结果，不依赖列表顺序、数据库返回顺序或最近学习时间。最小间距修正只在同屏主题数超过舒适密度时启用。
- 树精灵：一个纯绘制函数，输入尺寸、种子、色调，输出现有原型的同一组图元——地面投影、树干、两根枝杈、树冠叶簇、左上高光；随机只来自种子，同一棵树每次绘制一致。Android 用 `Canvas`/`Path`，Web 用 SVG；两端共享同一组归一化坐标常量，避免视觉漂移。
- 树大小：分支数映射到最小与最大两档之间，线性但有上下限；归档分支计入分支数，因此一段归档子树会让树略大，但纸条上会说明归档段数，不制造「归档也长新叶」的错觉。
- 选中与命中：命中区是树的整个包围盒且不小于 44 dp；点在两棵树的包围盒重叠处时按包围盒面积小者优先，避免大树挡住小树。
- 导航：点纸条箭头调用既有的「打开主题」路径；归档子树的进入仍走既有归档查看路径，不在森林里新开一条归档详情。

### 状态与错误

- 读取分两段：主题集合与分支计数可以分别失败。主题集合失败是整页错误态；某主题的分支计数失败时，该树按 1 段枝绘制并在纸条上不显示归档数，同时在脚注里省略段枝总数——降级读数不伪装成精确值。
- 空态判定以主题集合为空为准，不以统计为空为准；统计为空只影响脚注那一项。
- 加载态在首次读取完成前显示；重试重新走同一条读取入口，不清空已选中的树。
- 页面生命周期：进入森林不暂停主题内草稿，不改变任何主题的 `updated_at`，不写数据库。

### 契约与兼容

- 零 schema 变更：森林只读既有表；`TreeLearnSchema.DATABASE_VERSION` 不因本需求增加。人设需求会加 V5→V6 的三列，那是人设切片的事，森林切片不依赖它。
- 不改默认总览画布：`TreeCanvasWiring.load(topicId)` 与 `TreeLayout.compute(...)` 的归档排除行为保持原样；森林的「含归档」只发生在自己的聚合查询与树精灵里。
- 不改首页排序：森林不写主题行，抽屉入口也不写。
- Web 兼容：Web 只读 fixture，`forest` 视图不新增 API、不新增依赖、不手改 fixture；统计缺失时按上文降级。
- 文档回写：森林落地后回写 PRD 的 BASE-14，把「归档隐藏」的范围写死为常规导航与列表，不含森林回顾视图；同时更新 `android/README.md` 与 Web 的导航说明。

## Doubts（疑虑点）

- 未决疑虑 0 条。
- 已拍板（2026-09-23，用户本人）：范围取 B（观赏 + 成长统计）；入口取 A（抽屉扩展位 → 独立全屏森林页）；归档子树出现在森林里且与其他树完全同样式，不做视觉弱化；统计复用抽屉统计同一入口；零 schema，树布局尽量复用。
- 已拍板（2026-10-21，用户本人）：森林采用「斜俯瞰、能看到树干」的视角，不做垂直俯视；树的场景位置固定，不按最近学习重排；连归档子树一起画。
- 已拍板（2026-10-23，用户本人）：随「按照 harness，结合当前 UX 风格，进行开发，在 web 和 android 上」授权进入实现；Web 与 Android 同步交付同一信息架构。
- 已知取舍：
  - 主题数量增长后的性能尚未实测；按几十棵一次绘制，不做缩放画布。若实测超时，另开需求决定聚合或降级，不在本规格里预埋手势层。
  - `TreeLayout` 不复用于森林，理由是它解决的是分支树布局，硬套会把「主题之间的地块」伪装成分支；代价是森林需要一份自己的场景摆放纯函数与树精灵，这是两类不同的问题，不是第二套同构实现。
  - Web 没有真实统计与生成数据，因此 Web 的脚注不显示连续天数；这是诚实的缺失，不用假数补齐。
