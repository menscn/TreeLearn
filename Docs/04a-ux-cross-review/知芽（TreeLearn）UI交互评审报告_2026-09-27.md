## 0. 结论先行

- **5 维总分 13/25**，其中「视觉层次」与「执行精度」各 2 分，均**未达放行线**。
- **Anti-Slop 门控**：**不是典型 AI slop**（无紫/彩虹渐变、无伪造数据、无 emoji 顶替图标、无手绘插图）；但命中 **1 项 P0「破碎感」**。
- **判定：不可放行（需修正）**。
- 症结不在"不好看"，而在**状态反馈缺失 + 信息架构/命名混乱 + 重复冗余表达**——是**"半成品交互"**，不是"审美不及格"。
- 一句话：**概念有灵魂（根问题 → 讲透 → 学习树），但关键页在工程上"哑掉了"。**

## 2. 问题清单

### P0 — 阻断级

**P0-1 学习树页整屏无反馈，疑似坏页**（截图 4）
- **现象**：按钮区下方全空白，无树、无 loading、无空态、无错误提示；底部只剩一行极小字号文案与一个叶芽图标。
- **为什么是问题**：学习树是本品**唯一的品牌隐喻载体**，四态（加载/空/错误/正常）不分，用户第一反应是"App 坏了"。违反「系统状态可见性」。
- **建议**：补齐四态——加载中骨架或生长动效、空态引导（"你的第一棵树从这里长出来"）、错误态重试、正常态渲染。
- **验收**：断网 / 首次进入 / 已有数据三种情况截图互不相同。

**P0-2 「删除 KEY」无二次确认，不可逆**（截图 5）
- **现象**：删除按钮与「保存」等高并排，单击即删。
- **为什么是问题**：API Key 是本地唯一凭证，删除后核心能力全部失效且不可恢复。违反「防错原则」。
- **建议**：二次确认弹窗（写明后果）+ 取消 / 危险色确认；或删除后给 5 秒撤销 Snackbar。

**P0-3 首页首屏约 2/3 屏纯空白**（截图 2）
- **现象**：输入卡片以下、底部 Tab 以上全部空白，新用户无任何探索路径。
- **为什么是问题**：首屏是激活关键位，"空白"会被理解为"没内容/没做完"。
- **建议**：补三类功能性内容——示例根问题卡、历史学习列表、学习树入口卡。
- **注意**：**填空白要用功能性内容与状态，不要用装饰性大图/插画**（那才是真 slop）。

### P1 — 严重

| 编号 | 位置 | 现象 | 为什么是问题 | 建议 |
|---|---|---|---|---|
| P1-1 | 全局 | 「学习库」（Tab）/「学习树」（页）/「最近学习」（抽屉）/「学习统计」四套命名并存 | 关系不明，用户无法建立心理模型，违反一致性 | 按 §5 统一：学习库为容器 Tab，学习树为其内视图，「最近学习」更名「学习记录」，「学习统计」归入学习库或设置次级页 |
| P1-2 | 首页 / 详情 / 学习树 | 顶栏标题被状态栏、刘海/摄像头胶囊遮挡（截图 2「知芽」贴状态栏、截图 3 长标题截断、截图 4「树」字被压住） | 违反 Android WindowInsets 规范，信息不可读 | 顶栏加 `insets(statusBars + displayCutout)` 内边距 |
| P1-3 | 详情页底部 | 5 图标工具栏与输入区两套操作区并列；「对话气泡」与「发送」语义重复；「联网」二字孤悬空白 | 层级混乱、双焦点，用户不知道主操作是哪个 | 合并为单条底栏；刷新/复制/分享收进"更多"；「联网」改为带文字的切换 chip |
| P1-4 | 首页 / 详情 / 设置 | 「V4.1 Flash」出现两次、「DeepSeek 已就绪」一次、设置页「deepseek-flash」一次，模型状态四处冗余，且外泄内部版本号 | 信息重复 + 用户看不懂版本号，稀释品牌感 | 统一为"DeepSeek 就绪"；版本号只在设置页出现 |
| P1-5 | 抽屉导航 | 右缘无关闭按钮、无滑动提示；「你好」被当成学习记录列出；仅 1 条记录却占满整屏，「设置/学习统计」孤悬底部 | 可用性缺陷：关不掉、脏数据、空间浪费 | 加显式关闭按钮；写入前过滤问候类无效输入；补搜索/分组 |
| P1-6 | 详情页图标栏 / 设置页列表 | 关键操作纯图标无标签；设置项右侧统一用「···」表示"进入下一页" | 违反「识别优于回忆」；「···」语义是"更多操作"，与实际行为不符 | 关键操作加文字标签；设置项右侧改「›」箭头（进入页）或 Switch（开关） |
| P1-7 | 首页横向 chip / 抽屉右缘 | 「顺着…」等 chip 被边缘截断，无滚动指示 | 用户不知道还有内容可滑 | 加渐隐遮罩或改换行 |

### P2 — 打磨

- **P2-1** 黄色 logo 与深绿主色冲突 → 建议黄色降为点缀色
- **P2-2** 「连续学习」7 个方块语义不明、无星期标签，"1 天"却点亮多格（**推断**，基于像素判读）→ 加日期标签与图例
- **P2-3** 分组标题「DEEPSEEK API KEY」中英混排 → 统一中文
- **P2-4** 页面标题「设置」与底部 Tab「设置」重复 → 去掉其一
- **P2-5** 「发送」灰按钮对比度偏低 → 按 WCAG AA 提对比
- **P2-6** 学习树页底部文案字号过小（**推断** < 12sp）→ 提至 `fs-*` 最小档

## 4. 做对了、不该改（避免过度设计）

- ✅ 深绿 + 米白的配色基调（**勿加渐变/高饱和**）
- ✅ 连续打卡机制本身（只需改表达，不用改机制）
- ✅ "根问题 → 讲透 → 学习树"的产品哲学（最值钱的差异化，务必强化）
- ✅ Markdown 答案卡的内容层级（微调容器即可）
- ✅ "仅存本机"的隐私说明（建立信任，保留）

> ⚠️ 提醒：**勿用装饰性大图/插画去填首页与树页的空白**——那才是真 slop。要用功能性内容与状态去填。

## 6. 与工程既有约定的对齐

本报告结论需与 `.trae/rules/ux-design.md`「设计质量底线」交叉核对后落地：

- **触达**：可点击区域不小于 44×44 dp —— P1-6、P1-7 需按此验收。
- **对比度**：正文 4.5:1、大字 3:1 —— P2-5 按此验收。
- **间距**：所有间距落在 4pt 网格（`s1/s2/s3/s4/s6/s8`）—— 第 2 批 IA 调整时不得引入临场数值。
- **字号**：只取 `fs-*` 档位；`display` 与 `cap` 的对比是这套系统的性格，不要压平 —— P2-6、P1-2 受影响。
- **改设计的顺序**（若后续要落到设计稿）：先改原型 `:root` → 同步 `tokens.json` → 同步 `colors.xml` → 跑 `check_design_tokens.py`。
- **偏差记录原则**：设计稿与生产代码不一致时，**生产代码是事实，设计稿是意图**——记录偏差并单独路由修复，不静默改稿或改代码。
