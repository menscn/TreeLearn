# 代码复核报告模板（code-reviewer 产物骨架）

> 本文件是 `Docs/reviews/**` 报告的**唯一骨架**。角色正文见 `.codex/agents/code-reviewer.md`；
> 两者不互相复述：本文件只定字段与归档写法，不写「怎么审」。
> 机械检查：`python -X utf8 .codex/scripts/check_code_reviewer_agent.py`（只读，判这份骨架与角色文件是否还成对）。

## 归档位置

- 一份复核一个文件：`Docs/reviews/REVIEW-YYYY-MM-DD-<kebab-case>.md`。
- 不复用、不覆盖旧报告：同一片代码被重审时另起一份，旧报告留在原地作为当时读数。
- 日期取复核发生当天（不是被审代码的提交日期）；`<kebab-case>` 取被审切片或分支的短名。

## 复核对象

- **提交或工作树读数**：（`git rev-parse --short HEAD` 的输出，或写明「未提交工作树 + 哪几个文件」）
- **被审文件清单**：（逐条路径；一行一个）
- **改动意图来源**：（任务卡路径或口头需求的一句话复述，标出谁是作者）

## 读取路径

- **规则**：（本次按根 `AGENTS.md` 路由实际读到的规则文件，一行一个）
- **调用链**：（producer 与 consumer 各至少一处，写成 `文件:行`）
- **既有测试与证据**：（读了哪几支测试、哪份证据文件；没读的要写「未读」并说明为什么）

## 阻塞项

> 必须在合并前改掉的行为或形状。每条三段式：结论 / 定位 / 为什么。

- 结论：
- 定位：`文件:行`
- 为什么：
- 建议改法：

（每条阻塞项重复上面四行；没有阻塞项时在本节写「无阻塞项」，并在下方「读取路径」里保证文件清单已列全。）

## 非阻塞建议

- 结论 / 定位 / 为什么 / 建议改法，格式同上，逐条列出。
- 被实现者拒绝的建议保留原条并追加一行「**处置**：已拒绝，理由 …」；不反复提同一条。

## 待回答的问题

- 只放**问得出答案**的问题（每条注明谁来答：实现者 / 人 / 一次真实运行）。
- 已经能判定的事项不要写这里，写进对应严重度。

## 测试充分性

- **判据是否会转红**：（逐条写明哪条断言在注入违规时确实失败、失败时的实际读数；只有成功路径的测试要标为覆盖不足）
- **未覆盖的分支**：（错误路径、空值、超时、并发、状态迁移、兼容分支——按代码实际有的分支列）
- **实跑命令与退出码**：（原样粘贴命令、退出码与判据行；工具没跑就不能写成跑过）

## 重复实现与无生产者代码

- **同形逻辑**：（第二份实现的 `文件:行` 与它重复了哪一段）
- **无生产者分支/字段**：（先查过 producer 才能写；查不到要写「已用 <命令> 查，命中 0」而不是写「应该没人用」）
- **注释保留的死代码**：（一律建议删除，不建议留注释）

## 复核未覆盖之处

- 本次没做到的验证，逐条写明**为什么没做**（缺环境 / 缺设备 / 需要授权 / 会清用户数据）。
- 不得以「整体看起来没问题」代替这一节。

## 回落任务卡的条目

- 需要进入任务状态的内容列在这里，一条一行，指明应落到 `.codex/tasks/**` 的哪一类小节。
- 本节只是**建议回落**，不写验收结论：任务是否验收由 verifier 与任务卡自己判定，
  字段名也不与本模板重复（本文件不含 Verdict / Evidence / Gaps / Risks 这几个任务卡字段）。
