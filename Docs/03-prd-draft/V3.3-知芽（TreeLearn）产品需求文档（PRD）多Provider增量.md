## 1. 增量范围一句话

知芽从「仅 DeepSeek」扩展为「OpenAI 兼容多供应商」：用户在设置中心管理提供商与 Key，按用途为聊天/快速/翻译三条链路各选一个模型，对话页使用所选模型完成生成；全部数据与 Key 仍只留本机。

## 2. 用户故事

- 作为学习者，我想添加一个 OpenAI 兼容供应商（填名称、基址、Key），拉取它的模型清单，以便用我信任的模型学习。
- 作为学习者，我想让「标题/摘要这类杂活」走一个便宜的快速模型、正式回答走聊天模型，以便省额度。
- 作为学习者，禁用或删除一个供应商后，我不想在任何地方再看到它的模型，也不希望已有分工悄悄失效——回落要有提示。
- 作为学习者，一个 Key 都没配时，我要被明确引导去配置，而不是对着一个点了没反应的发送键。

## 4. 非目标（维持既有裁定）

自定义请求头/请求体（reject）、Gemini/Anthropic 原生协议（暂缓）、MCP/Agent 工作区（reject）、余额查询/二维码导入/拖拽排序/连接测试器（本期裁剪）、深色模式（defer）、搜索/语音/文件管理（各自独立规格 080/081/082，不随本增量）。

## 5. 验收（产品口径）

1. 新增一个 OpenAI 兼容供应商 → 拉到模型 → 启用 → 对话页选中其模型完成一次真实生成（真机）。
2. 禁用该供应商 → 其模型即时从全部分工选择器消失。
3. 删除被设为聊天模型的提供商 → 分工回落 + 提示，不崩溃、不产生空引用。
4. 删除全部 Key → 发送被拦截并引导；重新配置后恢复。
5. 存量用户升级：原有 DeepSeek 配置无损迁移（T-083 迁移证据）。
