## 各视角评审结论

### User 视角

**Consensus**

知芽（TreeLearn）已覆盖用户可感知的完整学习链路：从空状态提交根问题，以同一根标题识别主题，从稳定回答深入分叉，返回来源现场，通过移动导航或画布找回路径，并在失败后保持正确状态（PRD §5、§6.2.1 至 §6.2.15；需求基准 §五 BASE-05 至 BASE-19）。

**Issues**

1. 生成中或失败的部分回答被正确禁止分叉，但 PRD 只定义“不提供可执行的分叉行为”，没有规定用户如何理解禁用原因和恢复条件（PRD §6.2.11、§6.2.12 异常 1；需求基准 §八 BASE-15）。如果不修复，用户将体验为熟悉的划词或分支入口突然消失或不可用，却不知道应等待生成完成还是执行重试。该问题可由 UX 状态反馈解决，不改变业务规则。
2. 已归档非根子树可从搜索或已归档入口找到并整体恢复，但点击结果后的“查看详情”和“恢复整树”尚未被区分（PRD §6.2.6 第 7 条、§6.2.7 异常 4、§6.2.10 第 4 条；需求基准 §五 BASE-14）。如果不修复，用户将体验为不确定查看搜索结果是否已经改变归档状态。该问题可由 UX 将查看与恢复设计为两个明确动作解决。
3. 无可用 Key 时输入仅暂留当前界面，流程图会引导用户离开去配置 Key 后再返回，但保留输入的可见反馈和返回落点尚未表达（PRD §5.1、§6.2.1 异常 1、§6.2.14 第 1 至 3 条；需求基准 §五 BASE-05、BASE-18）。如果不修复，用户将体验为担心离开配置后丢失刚输入的根问题或追问。该问题属于 UX 导航与状态反馈，不需要增加持久草稿规则。

**Suggestions to Skip**

- 为上述状态增加完整引导教程或新手课程 → 理由：低保真中用就地提示、禁用态和清晰动作即可验证，新增教学流程超出个人自用 MVP。
- 为相似主题增加独立主题副标题、标签或 AI 分类 → 理由：会重新引入第二套主题身份或额外组织层级，违反根标题作为唯一显示身份的冻结规则（需求基准 §9.2）。

**Key Recommendation**

UX 低保真必须覆盖三组状态表达：部分回答的不可分叉原因与恢复条件、归档结果的查看与整树恢复分离、Key 配置往返时暂留输入仍可见；三者均作为交互验收项，不升级为新的业务决策。

### System 视角

**Consensus**

V3.0 已形成一致的数据与状态不变量：主题和根分支同时形成；主题身份唯一来自根标题；根不可归档；非根归档以完整子树传播；仅稳定回答可被引用；创建快照不可变；无可用 Key 不产生已提交树节点（PRD §6.2.1 至 §6.2.4、§6.2.10、§6.2.11、§6.2.14；需求基准 §五 BASE-05 至 BASE-08、BASE-14、BASE-15、BASE-18）。

**Issues**

无。未发现核心逻辑死结、数据模型冲突、跨模块互斥或与冻结边界不兼容的问题。

**Suggestions to Skip**

- 引入独立主题名或主题级归档状态 → 理由：会破坏根标题唯一身份及根不可归档的不变量，重新打开已闭环的状态冲突（需求基准 §五 BASE-06、BASE-14）。
- 允许部分回答冻结为可分叉版本或重试新增消息 → 理由：会违反稳定回答来源及原位重试不重复的规则（需求基准 §五 BASE-15、BASE-18）。

**Key Recommendation**

保持 V3.0 状态规则不变进入 UX；后续评审重点验证原型是否准确表达这些状态，不再要求 PM 对已冻结规则重复决策。

### Cost 视角

**Consensus**

现有功能均能追溯到冻结 Must，PRD 没有引入账号、跨端、云同步、主题第二名称、主题归档、自动分组、自由布局或完整学习平台等范围外能力（PRD §6.1、§6.3.1；需求基准 §五 Must/Won't have）。

**Over-Engineering**

1. F11“回答生成状态与分叉资格”和 F14“AI 与网络失败可恢复”重复描述部分回答保留、原位重试、不重复消息或分支、成功稳定后才可分叉（PRD §6.2.11、§6.2.14）。去掉重复职责仍然满足当前需求，因为可让 F11 成为回答状态的唯一规则来源，F14 只描述失败入口及引用 F11 的恢复结果；无需删除任何用户行为。

**Suggestions to Skip**

- 现在固定主题数量、最近使用数量、推荐条数、摘要刷新时点、上下文长度、搜索排序或提示文案 → 理由：TBD-02 已明确延期到原型试用与能力约束后决定，不应在本轮重新升级为决策（PRD §6.3.1；需求基准 §9.3）。
- 增加埋点、转化漏斗或业务 KPI 系统 → 理由：个人自用且用户明确本期不设业务指标，去掉后仍满足全部功能验收（PRD §3、§8；需求基准 §四）。

**Key Recommendation**

不扩大功能面；允许 UX 直接验证现有行为，并在后续文档整理时统一 F11/F14 的状态所有权，避免同一失败规则在两个模块长期漂移。

## 综合结论

**Final Proposal**

1. V3.0 PRD 按当前冻结边界通过交叉评审，可进入 UX 低保真环节；无需再回到需求澄清或 PRD 感染重写。
2. UX 低保真需明确表现三项非阻断状态：部分回答为什么不可分叉及何时恢复；已归档结果的查看与“恢复整棵子树”是不同动作；从 Key 配置返回后暂留输入仍在原位置可见。
3. UX 不得借表达上述状态新增持久草稿、独立主题名、主题归档、部分回答分叉或新的固定数量规则。
4. F11 与 F14 的重复可以在不改变任何行为的前提下做 L0 文档职责整理，也可保留到终稿统一引用，不阻断 UX。
5. TBD-01 继续作为发布或实际使用前的数据处理与告知核定事项；TBD-02 继续按原型试用与能力约束延期，二者均不是本次进入 UX 低保真的新增决策。

**Resolved Disagreements**

- User 视角要求解释部分回答禁用、归档结果动作及 Key 往返状态，System 视角认为核心状态已经完整 → 最终共识：业务规则不变，由 UX 通过禁用原因、状态提示和显式动作完成表达。
- Cost 视角建议合并 F11/F14，System 视角要求保留完整异常证据 → 最终共识：不删除任何行为，只统一状态所有权或在终稿通过引用去重，当前不阻断下游。

**Decisions Needed From You**

无新增核心 Decisions。主题身份、根/非根归档边界、Key 首次提交原子性、稳定回答分叉规则均已由 V3.0 基准冻结；本报告中的状态反馈交由 UX 表达。TBD-01 保持发布前核定，TBD-02 保持延期，不在本轮重新发起决策。

**Suggestions to Ignore for Now**

- 独立主题名、主题副标题、主题标签和主题级 AI 分类 → 会破坏根标题唯一身份或扩大 MVP。
- 主题归档、隐藏完整主题或根分支归档 → 与已冻结的根节点边界冲突。
- 部分回答版本树、从失败片段强制分叉或重试新增消息 → 与稳定来源及不重复规则冲突。
- 固定主题/最近使用/推荐数量、摘要频率、上下文长度、搜索排序和提示文案 → 已由 TBD-02 延期，不应重新升级为门禁决策。
- 账号、同步、云备份、分享、协作、其他模型和其他终端 → 明确超出 Android 本机个人自用范围。
- 商业 KPI、埋点和转化漏斗 → 用户明确个人自用且本期不设置业务指标。
