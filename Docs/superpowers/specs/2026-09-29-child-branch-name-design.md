# 子分支列表名称可见性修复

## 需求规格

### 背景

Android 聊天页点击回答操作栏中的子分支入口后，弹出的列表能够显示图标和点击箭头，但部分真实分支的名称为空。现有列表行已经绑定 `ChildBranch.title`，问题发生在名称进入 UI 之前的读取链路。

### 目标

- 子分支列表的每一行都显示非空名称。
- 保留已保存标题和首条用户问题的现有优先级。
- 对刚创建、尚未拥有首条用户问题或正式标题的分支，显示来源答案文本的临时名称。
- 不改变分支创建、跳转、弹窗关闭和刷新保留行为。

### 验收

1. 已保存标题存在时，列表显示已保存标题。
2. 已保存标题为空但首条用户问题存在时，列表显示首条用户问题。
3. 前两者都为空但来源答案存在时，列表显示来源答案的首句或首段。
4. 所有文本都为空时，列表显示明确的“未命名分支”，不再出现空白行。
5. 点击行仍传递原分支 ID；已有弹窗生命周期测试继续通过。

## 界面方案

### 行内容

每个子分支行保持现有横向结构：树形分支图标、分支名称、未读数量徽标、右侧箭头。名称沿用现有文本控件与字号、颜色和两行截断规则，不新增第二套视觉 token。

### 文本处理

临时名称只在读取阶段生成，不写回数据库。名称生成前去除首尾空白，将连续换行视为段落边界，并限制展示文本长度；截断由现有 TextView 的尾部省略负责。空白文本按无值处理。

### 可访问性与交互

名称文本仍属于可读内容，图标和箭头保持无障碍隐藏。行的最小点击区域、点击后关闭弹窗并打开目标分支的行为不变。

## 技术规格

### 单一判定点

`BranchHeading` 继续负责分支名称优先级：

1. 分支已保存标题；
2. 分支自身首条用户问题；
3. 来源答案文本的首句或首段；
4. 固定的“未命名分支”兜底。

UI 层只展示 `ChildBranch.title`，不在 `ChildBranchPopup` 或布局文件中重新推导名称。

### 数据流

`SqliteChatStore.children()` 读取子分支时，继续通过 `BranchChildren` 判断分支归属，并读取子分支自己的消息。若常规标题为空，则通过子分支保存的来源消息 ID 和来源修订 ID 读取来源答案文本，再交给 `BranchHeading` 生成最终展示名。

来源修订不存在或内容为空时视为无来源文本，不阻断子分支列表；判定继续落到“未命名分支”兜底。名称读取失败不改变原有分支 ID、未读数量和点击回调。

### 变更边界

- 修改 Android Java 数据读取与名称判定测试。
- 不修改数据库 schema、迁移、API、分支创建事务或异步生成协议。
- 不把临时名称持久化，避免覆盖后续 AI 生成的正式标题。

### 测试

- 为 `BranchHeading` 或其直接测试补充四种优先级用例。
- 为真实子分支读取链路补充来源答案兜底用例，覆盖来源修订缺失时的固定兜底。
- 保留并运行 `ChildBranchPopupLifecycleInstrumentedTest`，确认名称渲染、点击选择、刷新保留和关闭行为未回归。
- 运行 Android Java-only guard，并对修改文件执行 `git diff --check` 与 UTF-8/替换字符扫描。

## 疑虑点

- 来源答案是临时名称，不代表最终业务标题；正式标题生成后，列表下一次读取应自然切换到已保存标题。
- 同一来源答案可能被多个子分支复用，因此来源文本只能作为兜底展示，不能作为唯一身份或持久化字段。
- 如果来源修订被清理，固定的“未命名分支”仍保证列表可读，但无法恢复历史答案文本；这属于数据缺失而非 UI 点击失败。
- 当前工作树存在其他未提交 Android 与文档变更；实现时只修改本次名称读取和相关测试文件，不覆盖已有工作。
