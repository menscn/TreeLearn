## Problem（问题与背景）

- 长按 prose 文本需要较久且触点容错小，用户难以稳定触发文本选中。
- 用户点击第二次高亮后，当前实现先后台写入 SQLite，再重新读取并重绘，黄色反馈延迟约一至两秒。

## Users and scenarios（用户与场景）

- 用户在 Android 对话页阅读稳定回答时，长按一段 prose 文本打开六格选择菜单。
- 用户点击高亮后，希望当前选区立即显示黄色高亮；持久化失败时，界面恢复为权威存储状态并给出已有存储错误提示。

## Expected outcome（预期结果）

- 长按响应更快，目标约 300ms 触发；拖动超过系统触摸阈值、松手或取消时不触发。
- 不改变单击高亮的点击语义，不破坏文本拖动选择、滚动和现有 ActionMode 菜单。
- 高亮点击后立即出现黄色视觉反馈，后台持久化继续执行；失败时回滚，不产生假成功状态。

## Core flow（核心流程）

- 按下 prose → 启动短延迟长按候选 → 未移动且仍按住时按触点选择词并启动现有 ActionMode → 松手后继续使用现有菜单。
- 点击高亮格 → 基于当前 marks 生成即时 UI 投影 → 关闭菜单并保留投影 → 后台写入 SQLite → 成功后由权威读回确认，失败后由权威读回恢复旧状态。
- 中断：移动超过触摸阈值、松手、取消、页面离开或消息消失时取消长按候选；页面销毁时清理候选回调。

## Constraints and non-goals（约束与非目标）

- Java-only；不新增第三方依赖；SQLite 仍是高亮的唯一权威来源。
- 不把单击普通文本改成选词；不改变六格菜单顺序、ActionMode 句柄或高亮取消规则。
- 不新增遥测事件；本次只优化交互反馈，不改变业务数据结构和 API 契约。

## Open questions（开放问题）

- 已确认事实：用户 2026-09-29 确认采用更快长按但保留长按语义，不改成单击选词。
- AI 自主决定：长按具体延迟、词边界算法、预览回滚的内部实现，以及设备测试等待窗口。
- 未知项：不同厂商 TextView 对触摸和 ActionMode 的细节差异，需要真实设备回归验证。

## Decision record（决策记录）

- 决策权归属：交互语义由用户决定，技术实现由 Android owner 在现有契约内决定。
- 决策人：用户
- 决策日期：2026-09-29
- 终态：accepted
- 已作出的决定：短延迟长按；移动取消；不改成单击选词；高亮即时预览、后台持久化、失败回滚。
- 验收标准与证据：真机多次长按可稳定出现选区菜单；高亮点击后同一帧链路内出现黄色 span；持久化成功与失败路径均有测试；Java-only、Lint、定向 instrumentation 通过。
- 风险与后续范围：若特定厂商仍吞掉短延迟触摸，需要在不改变产品语义的前提下调整触摸桥；本任务不扩展到表格单元格选中。
