## Problem（问题与背景）

- 问题/背景：观察到的现象——产品现有两条找回路径（首页历史主题列表、总览画布）都是**功能性**的，解决「找回」；同日已 accepted 的抽屉统计（INTENT-2026-09-23-home-drawer-stats-heatmap）提供**数字激励**（热力图、连续天数、累计指标）。缺的是第三层：把所有主题按「一棵树」的隐喻**观赏性汇总**，承载「回头看自己种了多少树」的回顾情绪。推测的原因（未证实）：纯列表与纯数字给不了「成长实感」，树形视觉隐喻比两者更强。
- 用户/场景：单人自用，只有用户本人；在抽屉里想一眼看到自己全部学习足迹的视觉形态。

## Users and scenarios（用户与场景）

- 本期只有用户本人使用；真机体验验收由用户完成。
- 场景：打开抽屉 → 点「我的森林」入口 → 浏览所有主题以树形绘制的汇总视图 → 点击某棵树进入对应主题继续学习。

## Expected outcome（预期结果）

- 预期结果：
  - 存在一个「森林」视图，将本机全部（或选定范围的）主题以树形图形呈现，每棵树可点击进入主题。
  - 成长统计与抽屉统计**同源同口径**（连续天数、累计指标复用同一查询入口），不出现第二套统计。
  - 数据全部来自既有七张表，零 schema 变更。

## Core flow（核心流程）

- 核心流程（含中断、撤销、重试）：抽屉滑出 → 点森林入口 → 森林页加载既有主题数据并绘制 → 点树进主题（正常导航）/ 返回回抽屉所在首页。无破坏性操作，无撤销需求；绘制失败（本地 DB 异常）按既有数据层错误路径降级，显示空态或错误态，不影响抽屉其余功能。
- 输入/输出：输入为既有主题/分支表数据；输出为森林视图的绘制与导航跳转。
- 状态与异常：无任何主题时显示空态引导（去种第一棵树）；统计为空时对应卡显示空态文案，不显示 0 值误导（与抽屉 intent 口径一致）。

## Constraints and non-goals（约束与非目标）

- 约束：
  - Java-only、XML/View + 自绘 View；视觉遵循知芽 design token（生长绿、纸感、44dp 热区），过 `check_design_tokens.py`。
  - **统计单一数据源**：森林页的成长统计必须复用 INTENT-2026-09-23-home-drawer-stats-heatmap 移交清单切片 1 的 `:data` 统计查询入口，禁止新增平行口径（本仓失败案例库「一条规则两个正文」同构坑）。
  - 树形绘制尽量复用 `:tree-layout` 模块既有布局能力（project-brief 核实该模块已存在），不为森林新写一套树布局。
  - 抽屉内的森林入口是「快捷入口」：不改变学习库/主题列表的正典地位，与抽屉 intent 的「快捷 vs 正典」缓解口径一致。
- 权衡偏好：情绪价值优先于信息密度——森林页以观赏为主，统计卡为辅；复用优先于新建。
- 非目标（non-goals）：
  - 不在本批新增任何统计指标或口径（Token 四指标已按抽屉 intent 另立小批）。
  - 不做森林分享、导出图片、社交展示；不做账号、同步。
  - 不做 3D 化、复杂动效；不改正典主题列表与总览画布。
  - 不在森林页提供归档/删除等管理动作（管理仍在正典入口）。
