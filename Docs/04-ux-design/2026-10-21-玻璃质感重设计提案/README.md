# 知芽 · 玻璃质感重设计提案

> 状态：设计提案；A 方向（叠加 C 的 1px 高光边与更强通透）已于 2026-10-21 落地生产，见「落地状态」  
> 日期：2026-10-21  
> 入口：[index.html](index.html)

## 先看什么

1. 打开 [index.html](index.html)，并排看三套方向的同一张对话页。
2. 点进任一方向页，四屏同构：首页、对话、分支导航、学习库。
3. 方向页左侧有「背景模糊」和「玻璃不透明度」两条滑杆，可以实时看材质的容忍度。
4. 阅读区不跟随滑杆变化；这是刻意的，正文对比不拿来换通透感。

## 设计主张

**只换材料，不改骨架。**

保留：

- 官方芽形标识与 `生长绿`；
- 分支、继续追问、学习库的主题结构；
- 以阅读为中心的层级，以及现有真实文案；
- 浅色主题。

改变：

- 容器从纸感实色变成玻璃：半透明底、背景模糊、1px 高光边缘；
- 背景从平面暖纸变成有方向的光：雾、树冠阴影、散景和一道斜光；
- 圆角、边缘和字距向 iOS 的克制感靠拢，但不照搬 iPhone 的导航结构。

不引入：

- 紫渐变、emoji 图标、装饰性数据、用 SVG 手画的产品图；
- 深色主题；本次只处理浅色；
- 任何新依赖或外部字体。

## 三套方向

| | A 晨雾玻璃 | B 青苔温室 | C 浮光 |
|---|---|---|---|
| 一句话 | 白玻璃、薄雾绿、最接近 iOS | 青苔底、树冠阴影、品牌最强 | 超薄玻璃、几乎无边界 |
| 玻璃 | 62% · 28px · 150% | 52% · 26px · 170% | 30% · 18px · 135% |
| 阅读区 | 86% | 80% | 72% |
| 场景光 | 雾绿 + 暖沙 | 青苔 + 暖黄光斑 | 米金 + 日光 |
| 最适合 | 默认主题 | 品牌展示 / Pad | 浏览 / 封面 |
| 主要风险 | 存在感偏弱 | 长读疲劳、状态色要重校 | 可读性依赖背景 |

先落 A 最稳；B 用来补品牌记忆点；C 只建议用在短内容和展示面。混合方案是 **A 的结构 + B 的一层树冠阴影 + C 的 1px 高光边缘**，阅读底仍沿用 A 的 86%。

## 三条共同规则

1. **阅读区独立不透明度。** 顶栏、输入框、卡片可以用较低的玻璃不透明度；正文阅读区固定在 80%–86%，不跟随通透度滑杆。
2. **玻璃只做容器，不做正文底纹。** 正文始终落在可预测的浅色上，避免背景光穿过文字。
3. **降级不做假模糊。** 不支持 `backdrop-filter` 或低端 Android 上，直接用更高不透明度的静态玻璃；不用半透明叠一层噪声冒充模糊。

## 与现状的差异

- 首页把品牌锁定从导航栏移回页面中央，变成大字号品牌 hero；新增一句提案文案「把一个问题，种成一棵树。」，落地时可以替换或移除。
- 对话页保留无气泡的用户消息、知芽 AI 标识、复制 / 重生成 / 分叉操作，以及从回答继续追问的分支栈。
- 分支导航页保留「根分支 · 不可归档」、AI 总结和当前 0 子分支；补了一句空状态说明「从任意一条回答继续追问，新的分支会在这里生长。」
- 学习库保留搜索、进行中 / 已完成筛选和两张真实主题卡；补了一句「新的分支会自动收进学习库」。
- 四屏都使用 fixture 里的真实 Android 文案；首页输入框展示的是现有示例问题的草稿态。

## 落地顺序（选定方向之后）

1. 先确定方向、阅读区不透明度和低端机 fallback。
2. 改权威原型的 `:root`。
3. 同步 `Docs/04-ux-design/design-system/tokens.json`。
4. 同步 `android/app/src/main/res/values/colors.xml`。
5. 重新生成 `tokens.css`，不手改生成物。
6. 跑 `check_design_tokens.py` 及其 selftest，再按 UX / Android 规则做真机与对比度验证。

**提案阶段未修改任何生产文件。** 三个方向页里的数值最初只用来比较材质；用户选定后，落地数值按上表顺序进入权威 token 链，见下节。

## 技术注意

- **Android**：`backdrop-filter` 没有直接等价物；API 31+ 可用 `RenderEffect` 做背景模糊，低版本必须回退。玻璃层数要控制，避免滚动时每帧对大面积做 blur。
- **Web / 平板**：用 `@supports (backdrop-filter: blur(1px))` 包裹；不支持时退回实色玻璃。`prefers-reduced-motion` 下已关闭漂移和入场动画。
- **对比度**：A 的正文区风险最低；B / C 落地前必须重新测正文、次要文字、红 / 琥珀 / 蓝状态色的对比度。C 的 72% 是下限。
- **主题**：本次只有浅色。若以后做深色，玻璃的 tint、阴影和状态色需要单独一套，不能直接反相。

## 验证

2026-10-21 用 Playwright（Chromium 1.64）实跑：

- **1440 × 1000**：`index.html` 与 A / B / C 逐页打开，控制台和页面错误均为 0，`scrollWidth` 等于视口宽度，无横向滚动；三页各 4 屏全部渲染，`backdrop-filter` 生效。
- **控制面板**：A 默认 62% / 28px，B 52% / 26px，C 30% / 18px；拖动后三页均可到 76% / 40px，阅读区分别保持 86% / 80% / 72% 不变；「恢复方向默认值」能复位；「关闭场景光」勾选后确实移除场景光与模糊，取消后恢复。
- **390 × 844**：首页与方向页切到单列，页面 `scrollWidth` = 390，无横向滚动；手机框随栏宽缩到约 326px，四屏仍完整可读。
- **1280 × 900**：首页方向区为两列，无横向滚动；第三张方向卡单独换行，这是为保住手机框宽度做的取舍。
- 分支页的 AI 总结默认展开，超出卡片高度的部分以底部渐隐提示；落地时应接真实滚动或折叠，不应依赖渐隐。

**尚未在 Android 真机上验证 blur 性能与降级观感。** 这是选定方向后必须补的一步，不能用桌面 Chromium 的截图代替。
