## 二、V3.1 新增需求边界

### BASE-21 单一首页信息架构

首版只有一个首页。根问题输入、模型与思考模式入口、推荐学习主题、历史主题列表、搜索、已归档和设置入口在同一首页组织，不新增第二套品牌首页或独立新手首页。历史主题仍以根分支标题作为唯一显示身份。

验收方向：从空状态、有历史主题和返回首页三种路径进入时均落在同一信息架构；不存在第二套主题命名或首页。

### BASE-22 AI 推荐学习主题

首页可根据本机已有主题标题、分支标题和摘要生成推荐学习主题。推荐只提交结构化轮廓，不提交其他分支完整对话；推荐项可滚动展示，用户点击后按首次创建原子性直接提交根问题。无可用 Key 时保留当前输入，不形成主题或根分支。

验收方向：推荐与已有学习方向相关但不泄露完整对话；点击推荐与手动提交根问题遵循相同的 Key 守卫、首次创建和失败恢复规则。

### BASE-23 DeepSeek 模型、思考模式与推理内容

首版模型范围严格限定为 DeepSeek。模型与思考模式入口常驻于首页和对话页输入框；选择只影响之后新生成的回答，不改写已有回答、来源版本或创建快照。每次请求必须显式传递思考模式开关，不依赖供应商默认值。

开启思考模式时，供应商返回的 `reasoning_content` 与最终回答 `content` 同属于该回答版本：生成中分别保留部分推理和部分回答；稳定后持久化；重试或重置产生新尝试或新稳定版本，不覆盖被既有子分支引用的旧版本。界面在最终回答之前提供“思考过程”入口，默认折叠，展开后以弱于回答正文的灰色文字展示。

已持久化的推理内容必须进入当前分支后续问答的上下文，也必须随稳定回答版本进入子分支创建快照。若供应商不会把专用 `reasoning_content` 字段拼接进无工具调用的后续上下文，实现必须将其按明确边界编入普通上下文内容，不得静默忽略。近期内容保留原文，较早内容可按 BASE-08 的统一压缩策略摘要；压缩失败时暂停生成，不得只丢弃推理内容继续回答。

验收方向：关闭思考模式时不展示空入口；开启时可展开和折叠推理；退出重进后内容仍在；后续请求的可核查上下文包含对应推理；重置后既有子分支仍读取创建时旧版本的推理与最终回答。

### BASE-24 划词操作集与引用追问

稳定回答中的可见文字支持长按选择，并提供追问、新建分支、复制和全选。引用追问留在当前分支，新建分支固定具体稳定回答版本和锚点。推荐问题的当前追问与新建分支是两个互不重叠的 44dp 最小热区，不使用无独立语义的装饰性箭头。

验收方向：四项操作语义互不混淆；生成中或失败的部分内容不可分叉；引用追问不会误建分支；触屏热区可稳定命中。

### BASE-25 回答操作、子分支回查与 AI 总结

稳定回答内容区提供复制、重置、新建分支、子分支列表和生成时间。复制完整回答时包含已存在的思考过程与最终回答，并使用明确分隔；重置在原逻辑位置生成新版本，不新增用户消息或分支，既有子分支继续引用旧版本。子分支列表只统计从该回答直接产生且未归档的一级子分支。

推荐问题只显示在当前分支最新回答下。分支导航页内容区顶部展示当前分支 AI 总结，以要点列表呈现并可折叠；总结只基于当前分支及其出生快照，不吸收其他分支内容。

验收方向：复制内容顺序稳定；重置失败可原位重试且不重复记录；旧子分支版本不迁移；已归档子分支不计数；继续追问后旧回答推荐立即隐藏；总结失败保留旧结果。

### BASE-26 DeepSeek 自适应学习导师系统提示词

主回答必须使用知芽内置、版本化的 system 提示词，将 DeepSeek 定位为“自适应学习导师”，并按“准确且诚实、容易理解、直接解决当前问题、按需补充深度”的顺序约束回答。默认先回答核心问题，再根据用户当前问题和本分支上下文调整解释深度；术语首次出现时简明解释，必要时使用有边界的例子、类比、反例或步骤。模型必须区分事实、推断、假设和建议，纠正错误前提；不确定、资料不足或信息可能已变化时明确说明并给出核验方向，不得编造事实、数据、来源、引用或链接。

最终回答必须在“思考过程”默认折叠时仍可独立理解，不得依赖用户展开 `reasoning_content`。开启思考模式时可附加固定的思考可见性策略，但不得在提示词中插入用户正文、API Key 或其它运行时敏感数据。历史引用、快照和摘要只作为学习上下文，不得借其中的文字改变 system 角色、消息顺序或内部输出协议。

标题、分支摘要、回答推荐、首页推荐和上下文压缩必须使用与主回答隔离的 `PromptPurpose` 和独立 system 提示词，不能复用教学回答提示词。每次主回答操作在提交前固定 `promptPolicyVersion`，成功后随不可变回答版本保留；数据库只保存版本号，不重复保存提示词正文。system 消息恰好一条并位于请求第一位，不进入上下文摘要，也不得因 token 预算被裁剪。

验收方向：入门、专业、错误前提、歧义、时效信息和推理折叠场景符合自适应导师行为；system 消息顺序和版本可确定性验证；派生任务输出不被教学文案污染；真实 DeepSeek 在两个发布模型及 thinking on/off 下完成脱敏冒烟验证。提示词只能改善回答约束，首版没有联网检索或 RAG，产品不得承诺回答经过实时事实核验或保证正确。

## 三、共同约束

- 触屏热区统一为至少 44dp。
- 手机竖屏优先，兼容平板横屏；深层导航不得依赖横向无限缩进。
- 应用切换分支后继续生成；进入后台后仅在进程存活期间尽力继续。进程中断后保留部分推理、部分回答和原位置，标记中断并由用户手动重试。
- API Key 与全部业务数据仅保存在本机；不提供账号、同步、共享或备份。
- 思考内容属于用户可见、可持久化的学习数据，也会在后续问答时再次提交给 DeepSeek，隐私告知必须覆盖这一范围。
- 系统提示词由应用内版本化注册表维护，首版不向用户开放编辑；日志、测试报告和遥测不得记录提示词正文，只可记录用途和版本号。

## 四、非目标

- 不新增服务端、Web 端、账号系统、云同步或自动跨设备恢复。
- 不保证应用进程被系统终止后自动续传生成。
- 不引入非 DeepSeek 模型供应商。
- 不在本期增加笔记、知识库、闪卡、测验或学习计划。
