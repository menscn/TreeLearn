## 二、需求背景与发起原因
1. **业务现状与核心痛点**：
   - BASE-01：用户本人在普通 AI 聊天工具中提出 q1、阅读 a1 时产生 q2；探究 q2 及后续疑问后，a1 已在很上方，难以回到原处继续阅读。该现象来自用户本人描述，尚无频次、耗时或群体调查数据。
   - BASE-02：线性会话把从 a1、a2 等不同回答衍生的追问按时间混排，主问题与临时探索相互干扰，后续回答所用上下文不再专一。此为用户本人经历及判断，不外推为所有职场学习者的共同结论。
   - BASE-03：树状学习工具若为主题和根分支分别维护名称，用户会面对同一棵树的两套身份；若根分支可归档，完整主题可能从日常结构消失；若根问题被 Key 状态阻止后仍创建主题或根分支，则主题列表会留下未真正开始的空树。
2. **根因假设**：线性对话无法同时固定疑问来源、隔离探索路径并恢复阅读现场；树状工具还必须统一主题显示身份与根分支标题、限制根节点整理操作，并明确首次提交的原子边界，才能保持结构一致。群体层面的发生频率和收益尚未经外部用研验证，列入第八章。
3. **不做 vs 做的价值对比**：
   - **不做**：用户继续在长会话中滚动寻找原回答，或另开聊天并复述背景；产品内部还可能出现主题名与根标题不一致、根分支归档后整树隐藏、被阻止的根问题产生空主题等状态冲突。具体时间损失未量化。
   - **做了**：用户可在本机创建和管理多个学习主题，从稳定回答建立隔离分支，探索后返回来源位置；主题列表始终用根分支标题表示同一棵树，根分支不可归档，无可用 Key 时不产生树节点。以第五章功能验收场景判定，不声称已有业务收益。
4. **当前替代方案及痛点**：
   - 用户现在怎么凑合解决：在普通 AI 聊天中连续追问并向上滚动寻找 a1；另开聊天并复述上下文是可行替代路径，但不是已证实的本人固定习惯。
   - 替代方案的代价：原阅读位置和疑问来源难以迅速找回，跨问题记录混入当前路径；未收集耗时、错误率或群体数据。

## 三、目标用户画像与使用场景
1. **用户分层与排他**：
   - 核心用户：因工作需要，持续用 AI 对陌生领域进行系统学习的职场人；本期实际使用与验收以需求发起人本人为准。BASE-04。
   - 次要用户：本期不定义次要用户群，个人自用不承担群体推广验收。
   - **非目标用户**：其他泛自主学习者不是首版重点；不据此扩展课程、考试或泛兴趣学习专属流程。BASE-04。
2. **JTBD（核心任务成败标准）**：当用户为工作学习陌生知识时，能从空状态提交根问题并形成以根标题标识的主题；读到 AI 稳定回答中的疑惑时，能保留来源并另开独立路径深入追问；只有探索后可回到来源继续学习、主分支未被子分支污染，并可从主题列表再次打开该树，任务才成功。BASE-01、BASE-05 至 BASE-08。
3. **高频场景链路**：此处“高频”指产品核心链路，不代表已有频率数据。
   - 场景1：用户首次进入空状态 → 输入根问题并尝试发送 → Key 可用时提交主题与根分支，根问题成为临时标题的来源 → AI 仅依据根问题生成一次正式根标题 → 主题列表显示该根标题 → 用户退出后再次打开主题继续学习。BASE-05、BASE-06。
   - 场景2：用户阅读 a1 时选中文字或针对整条稳定回答提出 q2 → 主动创建子分支并连续追问 → 返回父分支的 a1 和离开位置 → 在父分支继续学习；子分支内容不进入父分支正常回答。BASE-07 至 BASE-09。
   - 场景3：用户在子分支再次分叉形成多层树 → 从逐层导航或总览画布查找目标分支 → 查看来源、标题和摘要 → 进入分支恢复阅读位置。BASE-10 至 BASE-12。
   - 场景4：用户离开正在生成回答的分支 → 回答完成后该分支及折叠祖先提示未读 → 用户打开分支，让最新回答进入可视区域后清除未读。BASE-13。
4. **低频/边缘场景**：无可用 Key 阻止首次根问题；父稳定回答重生成；回答中途失败并保留部分内容；归档非根父分支及整棵子树后整体恢复；永久删除分支子树或整个主题；Key、网络、命名、摘要或上下文压缩失败。规则见第五、六章。BASE-05、BASE-07、BASE-14、BASE-15、BASE-18、BASE-19。

## 四、核心诉求与业务目标
1. **核心诉求排序**：
   - 诉求1：用户能在本机从空状态建立多个学习主题，以根分支标题作为主题唯一显示身份，并重新进入已有主题继续学习。BASE-05、BASE-06。
   - 诉求2：用户能从选中文字或整条稳定回答创建独立探索分支，返回后恢复原阅读现场，且各分支的正常回答上下文保持隔离。BASE-07 至 BASE-09。
   - 诉求3：用户能在任意深度的真实对话树中找到已探索方向，并通过稳定标题、动态摘要、推荐问题和未读状态继续学习。BASE-10 至 BASE-13、BASE-16。
   - 诉求4：用户能无歧义地整理非根子树和处理失败状态；根分支不会被归档，部分回答不会成为新分支的历史依据，被 Key 阻止的根问题不会产生树。BASE-05、BASE-14、BASE-15、BASE-18。
2. **核心指标表**：个人自用，用户明确本期不设置业务 KPI，不虚构分子、分母、基线和目标；采用第五章功能验收方向评判首版。

| :--- | :--- | :--- | :--- | :--- |
| 业务 KPI 不适用 | 用户明确本期不设业务指标，因此无分子、分母或当前基线；不把功能测试通过率伪装成业务指标 | 本期不设 | 本期不设 | 不适用 |

3. **护栏指标**：本期不设数值型护栏；功能验收不得出现主题显示名与根标题分离、无可用 Key 后留下主题或根分支、根分支被归档、跨分支回答串扰、父分支后续内容改写出生快照、部分回答被用于分叉、失败重试重复创建消息或分支，以及未明确告知的数据丢失。BASE-05 至 BASE-08、BASE-14、BASE-15、BASE-17 至 BASE-19。
4. **体验目标**：用户能完成“空状态提交根问题—以根标题识别主题—深入分叉—找回来源—退出后重开主题”的完整链路；移动端深层级和大量同级分支仍可通过逐层导航、更多、搜索及画布识别延伸方向。BASE-05、BASE-06、BASE-09 至 BASE-11。

## 五、需求边界与优先级划分（MOSCOW）
1. **Must have**：
   - BASE-05 多主题生命周期与首次创建原子性：首版支持多个本机学习主题。首次无主题时展示可输入根问题的空状态。用户尝试发送根问题时，若 DeepSeek API Key 未配置、无效或额度不足，则阻止发送，不提交主题和根分支；用户输入可暂时保留在当前界面，但不形成树节点。Key 可用且根问题成功提交后，主题与根分支作为同一次用户结果形成；此后的网络、超时或回答生成失败按 BASE-15、BASE-18 保留主题、根问题与根分支。主题列表用于打开已有主题，退出再打开时回到该主题上次使用的分支和阅读状态；用户可经确认永久删除整个主题，删除后全部本机数据不可恢复。最小范围不设固定主题数量。对应场景1。验收方向：验证无 Key、无效 Key、额度不足均不增加主题或根分支；配置可用 Key 后提交只形成一个主题和一个根分支；后续回答失败与重试不产生第二个根分支；支持第二个主题、退出重开、取消删除和确认删除。
   - BASE-06 主题显示身份与根标题：主题列表直接复用根分支标题，不设置独立主题名字段或第二套命名状态。根分支临时标题来自根问题；AI 正式标题仅依据根问题生成一次，不随对话自动变化。用户手动修改根标题或主动刷新根标题时，主题列表同步显示更新结果；主动刷新仍仅依据根问题生成，刷新失败保留原根标题。对应场景1。验收方向：主题列表标题始终与根分支标题一致；修改或刷新后两处同步；连续对话、摘要更新不自动改变根标题；数据中不出现独立主题名。
   - BASE-07 独立对话树与稳定来源：一个主题对应一棵树，一个节点对应一条可连续追问的独立对话分支；普通追问留在当前分支，只有用户主动新建分支才增加节点，逻辑深度不设产品层级限制。分叉固定来源消息、稳定回答版本及选中文字或整条回答。对应场景2、3。验收方向：同一稳定回答可创建多个兄弟分支并继续深层分叉；旧稳定回答重生成后，既有子分支仍连接创建时版本。
   - BASE-08 分层上下文与创建快照：子分支保存创建时的来源版本、锚定内容、上游背景和阅读位置；正常回答只使用本分支对话及出生时上游快照，近期内容保留原文，较早内容使用摘要；不读取兄弟、子分支或父分支后来新增内容。对应场景2。验收方向：父分支继续聊天或重生成后，既有子分支依据不变；其他分支内容不出现在正常回答上下文。原文长度、摘要长度及切换阈值不在本基准固定。
   - BASE-09 聚焦阅读与恢复：阅读页只显示当前分支的连续对话；离开时保存阅读位置，重新进入时恢复；返回来源回答时定位触发分支的选中文字或整条回答。对应场景2。验收方向：从长回答中分叉并多轮追问后，返回父分支可恢复离开位置和来源标记。
   - BASE-10 移动端逐层导航：显示祖先路径、当前分支和直接子分支；点击节点直接进入对话。子分支较多时使用最近使用、更多和搜索，不做自动语义分组；深层级不依赖持续向右缩进。折叠状态按主题本机保留。对应场景3。验收方向：深层节点可逐级回到祖先；同级分支很多时可通过更多与搜索定位目标。
   - BASE-11 总览画布：提供总览入口，以自动树布局展示真实父子关系；节点包含分支名和本分支摘要，并显示未读、子分支数量与折叠状态。画布支持平移、缩放、折叠子树、搜索定位和回到当前分支；缩小时可只显示标题，选中节点查看完整摘要、来源回答和锚定原文，再选择进入对话。节点不可自由摆放；新增分支或摘要变化时尽量保持当前视野及所选节点稳定。对应场景3。验收方向：折叠后仍可识别后代数量和未读汇总；查看详情并跳转后可回到画布位置。
   - BASE-12 非根分支标题、摘要与搜索：非根分支创建时由首问形成临时标题，AI 再结合来源锚点与首问命名一次；标题不随对话自动变化，用户可手动修改或主动刷新。所有分支摘要均随本分支对话自动更新，不吸收其他分支；命名或摘要失败保留原值。搜索覆盖主题所复用的根标题、其他分支标题、用户问题、稳定或部分 AI 回答及锚定原文，结果显示祖先路径及归档状态。对应场景3。验收方向：连续追问不改标题；非根标题主动刷新失败不覆盖旧值；摘要更新无兄弟内容；搜索可定位日常与已归档非根分支。根标题规则以 BASE-06 为准。
   - BASE-13 未读状态：只有分支产生用户尚未看到的 AI 回答时显示实心蓝点；折叠祖先显示后代未读汇总，推荐问题不算未读；打开分支且最新未读回答进入可视区域后才清除。对应场景4。验收方向：离开生成中的分支后回答完成，分支与折叠祖先均提示；仅进入但未看到最新回答时不清除。
   - BASE-14 非根子树归档与永久删除：根分支不允许归档，首版不提供隐藏完整主题的能力；完整主题在主题列表中只能保留或经确认永久删除。仅非根分支可归档；归档非根父分支时，其整棵子树作为一个单元从日常逐层导航和默认画布隐藏，可经“已归档”入口或搜索找到并整体恢复，归档或恢复均不重接后代。永久删除非根父分支时，先说明受影响的子树数量并确认，确认后连同全部后代删除；删除根分支按删除整个主题处理。对应边缘场景。验收方向：根分支无可执行归档行为；非根父分支归档后全部后代退出日常视图，恢复后关系完整；主题列表中不出现主题归档或隐藏；取消永久删除不改变树。
   - BASE-15 回答生成状态与分叉资格：生成未完成或失败时，已产生的部分回答保留并可阅读，但不可被选择为新分支来源。用户可在原位置手动重试，重试不得重复创建用户消息或分支；只有重试成功后的稳定回答版本可供选中文字或整条回答分叉。已有稳定回答及其子分支继续遵循固定版本锚点。对应边缘场景。验收方向：生成中和失败的部分回答均无分叉能力；原位重试前后消息与分支数量不重复；成功稳定后才能分叉。
   - BASE-16 推荐问题：推荐生成可参考当前回答及整棵主题树的结构化轮廓，包括已探索标题、来源锚点和简短摘要，以减少重复；它不把其他分支完整对话带入正常回答。点击推荐文字在当前分支继续追问；点击旁侧新建分支图标，从当前稳定回答的具体版本创建子分支。对应场景2。验收方向：已有方向影响推荐但不污染正常回答；对生成中或失败的部分回答不提供可执行的新分支创建行为。
   - BASE-17 本机个人数据与 AI 配置：首版仅 Android，无登录、跨设备、云同步、共享或备份；主题列表、主题树、消息及状态、快照、标题、摘要、未读、阅读位置和 API Key 全部仅本机保存。用户自行配置 DeepSeek API Key，可掩码展示、替换和删除；卸载或清除应用数据后不可恢复。对应全部场景。验收方向：替换或删除 Key 后配置状态更新；应用中不存在账号、同步和共享能力；本机业务数据中不存在独立主题名字段。
   - BASE-18 AI 与网络失败可恢复：Key 未配置、无效或额度不足时阻止发送并引导配置或更换；对根问题按 BASE-05 不落主题和根分支，对既有主题内的提问保留用户输入但不新增已提交消息或分支。断网、超时或回答生成失败时，保留已提交的用户问题、分支结构、来源锚点及已产生的部分回答，按 BASE-15 原位手动重试。对应边缘场景。验收方向：逐一模拟上述失败，检查首次创建原子性、既有树不受损、部分回答分叉资格及重试不重复。
   - BASE-19 AI 辅助生成降级：根或非根标题命名失败时保留临时或旧标题，摘要失败时保留旧摘要；上下文压缩失败时暂停本次回答并提示重试，不静默丢失上游背景。对应边缘场景。验收方向：分别模拟标题、摘要和上下文压缩失败，原有可用内容不被失败结果覆盖，根标题与主题列表仍保持一致。
2. **Should have**：本期未确认可延后的独立增强项；上述 Must 均为用户确认的首版闭环，不擅自降级。
3. **Could have**：本期无已确认的候选增强项；未来新增需重新确认边界。
4. **Won't have**：
   - 自动语义分组和自由拖动节点：树应忠实呈现真实对话关系，首版以最近使用、更多、搜索和自动树布局解决查找。BASE-10、BASE-11。
   - BASE-20 学习平台扩展：笔记、知识库、闪卡、学习计划、测验和进度统计不是验证树状分支学习主流程所必需，本期不纳入。
   - 登录、云同步、共享、备份及跨设备：用户明确首版为本机个人工具。BASE-17。
   - iOS、Web 和桌面端：用户明确首版仅 Android。BASE-17。
   - 独立主题名字段或第二套主题命名状态：主题列表必须复用根分支标题。BASE-06。
   - 主题归档或隐藏、根分支归档：完整主题只能保留或确认后永久删除。BASE-14。
   - 自动把子分支结论带回父分支、自动随对话改变标题：会破坏上下文隔离和稳定命名。BASE-08、BASE-12。
   - 归档后代单独留在日常树中、删除中间节点后自动重接后代、从部分回答创建分支：会破坏真实父子关系或版本锚点。BASE-14、BASE-15。

## 六、约束条件与前置依赖
1. **硬性约束**：
   - 技术/业务约束：产品标准名称统一为“知芽（TreeLearn）”；仅 Android 移动 App；支持多个本机学习主题；主题显示身份唯一来自根分支标题；根分支不可归档；用户自配 DeepSeek API Key，首版仅支持 DeepSeek API；正常回答与推荐问题的可读上下文边界不同；仅稳定回答可作为分支来源。上述为产品规则，不指定技术架构。BASE-06、BASE-08、BASE-14 至 BASE-17。
   - 合规/安全约束：Key 仅本机保存并以掩码展示，可替换、删除；主题、消息和快照不提供同步、共享和备份。调用外部 AI 时，完成该次生成所需内容会交给 DeepSeek 处理；具体数据处理条款和应用内告知尚未核定，不得宣称全程离线或外部服务不接触内容。
2. **外部依赖与降级策略**：
   - 依赖项：用户提供可用且有额度的 DeepSeek API Key；AI 回答、推荐、命名和摘要依赖对应能力。未指定其他模型供应商或备用服务。BASE-17。
   - 接入核对来源：用户提供的 [DeepSeek 官方开发文档](https://api-docs.deepseek.com/zh-cn/)；该开发文档不代表数据处理条款、隐私告知或实际使用方式已经核定，相关事项仍见 TBD-01。
   - 降级策略：无可用 Key 时按 BASE-05、BASE-18 区分首次根问题与既有主题，不产生已提交的无效树节点；断网、超时或生成失败按 BASE-15、BASE-18 保留数据、限制部分回答分叉并允许原位手动重试；标题、摘要和上下文压缩失败按 BASE-19 处理。
3. **TOP 3 风险及预案**：
   - 风险1：深层、多主题或多兄弟分支使用户难以定位 → 主题列表统一使用根标题，逐层导航、祖先路径、最近使用、更多、搜索及可折叠画布共同提供找回路径。BASE-06、BASE-10、BASE-11。
   - 风险2：根身份分裂、根归档、父回答变化或部分回答分叉导致历史结构冲突 → 只保留根标题这一套身份，禁止根归档，固定稳定回答版本，部分回答不可分叉。BASE-06 至 BASE-08、BASE-14、BASE-15。
   - 风险3：外部 AI、Key 或本机数据失效影响学习记录 → 首次创建按可用 Key 保持原子性；其他失败保留已有结构并允许重试或换 Key；明确无备份，删除主题、卸载或清除数据后不可恢复。BASE-05、BASE-17 至 BASE-19。设备故障恢复不在本期范围。
